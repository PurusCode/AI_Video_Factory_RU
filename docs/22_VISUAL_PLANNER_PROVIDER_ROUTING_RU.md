# Маршрутизация провайдера для визуального планировщика

Дата: 2026-11-06

## Почему добавлено

Визуальный планировщик выполняет более тяжёлую задачу, чем семантическая разбивка:
он формирует режиссёрские указания, стратегии ресурсов, экранный текст, визуальные
вставки, claims и дополнительные метаданные на каждую сцену. В наблюдаемом запуске
MWS `video-farm-gemma-4-31b-test` регулярно превышал таймаут 120 секунд, тогда как
локальный `qwen2.5:14b-instruct` возвращал валидный ответ за примерно 161 секунду.

Чтобы не менять поведение других этапов, добавлена отдельная настройка только для
visual planner.

## Переменная окружения

```dotenv
SEMANTIC_VISUAL_PLANNER_PROVIDER=secondary
```

Допустимые значения:

- `auto` — поведение по умолчанию, использовать общий порядок провайдеров из `.env`
  (обычно MWS, затем Ollama);
- `primary` — использовать для visual planner только первичный провайдер;
- `secondary` — использовать для visual planner только резервный провайдер.

При значении `secondary` визуальный планировщик сразу отправляет запросы в Ollama
и не тратит 120 секунд на заведомо таймаутящийся MWS. Другие этапы, включая
`storyboard.py`, продолжают использовать исходный общий маршрут MWS → Ollama.

Настройка применяется при запуске команды `semantic_cli plan`. Для уже работающего
процесса изменение `.env` не действует: нужно остановить процесс и запустить команду
снова. Прогресс не теряется благодаря `storyboard_planned.progress.json`.

## Откат

Удалить `SEMANTIC_VISUAL_PLANNER_PROVIDER` из `.env` или установить `auto`.

# A/B-проверка качества русской озвучки

- **Версия документа:** 1.3
- **Дата актуализации:** 05.11.2026
**Цель:** выбирать TTS по реальному звучанию и работоспособности на целевой Windows-машине, сохраняя отдельные исторические результаты. Успешное создание WAV само по себе не доказывает пригодность озвучки для публикации.

## 1. Актуальное решение

Основной TTS проекта выбран: **Kokoro-ru v2, голос Dima**.

Пользовательская оценка естественности Kokoro Dima от 03.11.2026 — **4/5**. Внутренний порог проекта — не ниже 4/5 — достигнут.

Piper Dmitri получил пользовательскую оценку **2,5/5** и не выбран для производства.

Решение закреплено в:
- `docs/DECISION_TTS.md`;
- `docs/11_KOKORO_PRODUCTION_AND_LICENSE_DECISION.md`.

**Ограничение статуса:** Kokoro пока проверен в изолированном benchmark-окружении. Основной CLI ещё не переведён на Kokoro. Производственная интеграция и полный E2E-прогон остаются невыполненными.

## 4. Контрольный материал и процедура

Основной контрольный сценарий: `data/tts_quality_benchmark_script.json`.

В сценарии присутствуют:
- нейтральная связная русская проза;
- числа, даты, время и проценты;
- английские технические термины и аббревиатуры;
- паузы, перечисления и знаки препинания;
- потенциально неоднозначные ударения.

Для воспроизводимого сравнения необходимо сохранять исходный JSON, версию нормализатора, нормализованный текст, WAV, manifest, runtime и время синтеза. При изменении сценария результат фиксируется как отдельная версия; результаты разных сценариев нельзя выдавать за A/B на идентичном материале.

Оценивать отдельно:
1. естественность;
2. разборчивость;
3. ударения и произношение;
4. паузы и пунктуацию;
5. техническую стабильность;
6. скорость и использование RAM;
7. лицензионные условия.

## 5. Критерии приёмки

Шкала каждой субъективной оценки — от 1 (плохо) до 5 (отлично).

| Критерий | Условие |
|---|---|
| Естественность | Не ниже 4/5; нет явного впечатления роботизированной речи |
| Разборчивость | Не ниже 4/5; слова понятны при обычной громкости |
| Ударения и произношение | Не ниже 4/5; критические ошибки должны быть исправимы и покрыты тестами |
| Паузы и пунктуация | Не ниже 4/5; нет случайных разрывов и сбивчивого темпа |
| Техническая стабильность | WAV валиден; длина не аномальна; процесс завершается без ошибки/OOM |
| Производительность | Время и RAM измеряются на целевой машине |
| Права | Условия модели/датасета документированы; принятый остаточный риск отражён в ADR |

**Отклонить** образец, если естественность ниже 4/5 или пользователь считает речь явно роботизированной, даже когда все слова разборчивы. Это внутренний критерий проекта, а не универсальный стандарт TTS.

## 6. Исторический результат Kokoro ONNX на Windows — 25.10.2026

Команда завершилась успешно, созданы четыре блока и `manifest.json`:

```powershell
.\.kokoro-venv\Scripts\python.exe -X utf8 .\tools\kokoro_onnx_benchmark.py --script data\tts_quality_benchmark_script.json --out output\kokoro-dima-benchmark --voice dima --threads 2
```

Зафиксированные параметры:
- Repository revision: `d649c57`.
- Python: 3.13.14 x64.
- ONNX Runtime: 1.31.0.
- NumPy: 2.5.4.
- RUAccent: 1.5.8.3.
- Misaki: 0.9.4.
- phonemizer-fork: 3.3.2.
- SHA-256 модели: `e5bc91f0b15fa85886a82a4fb87e2345fc3de3e6025820a059dde215eb154071`.
- SHA-256 voice pack: `e774e8859604164aa27c393fa4393c3a4ff2162d37911a39574551edbc801dcb`.

Длительность блоков:
- `narrative`: 29,005 с (2 IPA-части);
- `numbers_dates`: 19,375 с;
- `technical_terms`: 21,55 с;
- `punctuation_and_pauses`: 17,2 с.

Итого:
- аудио: 87,13 с;
- инференс: 26,91 с;
- RTF: около 0,309;
- скорость: около 3,24× real time.

Пиковая RAM не измерялась. Для `narrative` применялось разбиение на две части из-за ограничения длины IPA. Предупреждение `[transformers] PyTorch was not found` не остановило ONNX Runtime generation. Не устанавливать PyTorch только ради устранения предупреждения, если выбранный ONNX-путь работает.

На дату этого теста пользовательская оценка Kokoro составляла 3,5/5, а Piper — 2,5/5. Эти значения являются историческими.

## 8. Автоматическая нормализация `voice_text` — 25–26.10.2026

В `src/video_farm/text_normalization.py` добавлен ограниченный нормализатор для явно поддерживаемых шаблонов: даты, время, проценты, известные единицы измерения, валюты и некоторые обозначения моделей.

Принцип работы:
- `text` остаётся редакторским/экранным текстом;
- `voice_text` отдельно подготавливается для синтеза;
- неподдерживаемые числовые шаблоны не должны преобразовываться без контекста;
- неразобранные цифры отражаются в `unconverted_numeric_tokens` и требуют ручной проверки.

### 8.1. Версия v0.2.0 — 25.10.2026

Добавлен первый ограниченный автоматический нормализатор. В контейнерном окружении 30 unit-тестов проходили с тестовым двойником конвертера. Реальный `num2words` в том контейнере отсутствовал из-за недоступности PyPI.

### 8.2. Версия v0.2.1 — 25.10.2026

Коды падежей стандартизированы на короткие `n/g/d/a/i/p`. Исходный код `num2words 0.5.14` поддерживает и английские aliases; изменение является стандартизацией API, а не доказательством того, что прежние aliases обязательно вызывали ошибку.

Добавлен интеграционный тест настоящего `num2words`. Историческая проверка контейнера: 30 passed, 1 skipped.

### 8.3. Версия v0.2.2 — 26.10.2026

После проверки реального вывода на Windows обнаружен дефект рода для женских единиц: например, `2 минуты` могло превращаться в `два минуты`; такая же проблема была в записи времени `14:02`. Также обнаружена нежелательная глобальная замена тире запятой.

В v0.2.2 внесены:
- женские формы числительных для известных женских единиц;
- женская форма минут в записи времени;
- сохранение тире;
- regression tests на 1/2/21/22 минуты/секунды, время и конструкции с тире.

Историческая контейнерная проверка: 33 passed, 1 skipped. Пропущен интеграционный тест настоящего `num2words`, отсутствовавшего в том окружении. Позже пользователь подтвердил установку настоящего `num2words 0.5.14` на Windows с v0.2.1; патч v0.2.2 должен рассматриваться отдельно от этого более раннего прогона.

## 10. Актуальная оценка Kokoro — 03.11.2026

Пользователь повысил оценку естественности Kokoro-ru v2 Dima до **4/5**. Внутренний порог качества проекта достигнут.

Оценка 3,5/5 от 25.10.2026 сохраняется как историческая. Она не является текущей оценкой. Piper Dmitri остаётся на 2,5/5.

Эта оценка относится к естественности голоса и не доказывает качество длинного производственного ролика, синхронизацию речи с визуальным рядом или отсутствие ошибок во всех возможных контекстах.

## 11. Повторный изолированный CPU benchmark Kokoro — 05.11.2026

На целевой Windows-машине в отдельном окружении выполнен повторный benchmark:

- четыре блока контрольного сценария;
- суммарная длительность аудио — около 93,4 секунды;
- RTF по блокам — приблизительно 0,295–0,317;
- средний RTF — около 0,307;
- inference выполнялся на CPU, дискретная видеокарта не использовалась;
- manifest сформирован;
- конфигурация ударений соответствует проверенной конфигурации;
- в проверенных блоках не осталось необработанных числовых токенов.

Значения 93,4 с и RTF 0,307 относятся к прогону 05.11.2026. Они не заменяют значения 87,13 с и 0,309 от 25.10.2026.

Этот прогон подтверждает работу изолированного runner на целевой машине. Он не подтверждает, что основная команда `video_farm.cli tts` использует Kokoro.

## 14. Вывод и следующий этап

На основании пользовательской оценки от 03.11.2026 и технических результатов от 05.11.2026:

- Kokoro-ru v2 Dima выбран основным TTS;
- субъективный порог естественности 4/5 достигнут;
- изолированная генерация на CPU работает со средним RTF около 0,307;
- нормализация и контекстные ударения проверены на имеющемся контрольном наборе;
- Piper Dmitri не выбран из-за пользовательской оценки 2,5/5;
- интеграция Kokoro в производственный CLI ещё не выполнена;
- полный E2E-рендер и ручная приёмка готового ролика ещё не выполнены;
- §3 Dialogs OpenRAIL остаётся принятым документированным остаточным риском и не блокирует локальную интеграцию согласно ADR.

### Критерии следующего этапа

1. `video_farm.cli tts` синтезирует через Kokoro Dima.
2. API синтеза и структура результата совместимы с остальными модулями.
3. `manifest.json` содержит блоки, WAV, длительность, движок, модель, revision, SHA-256 и сведения о нормализованном тексте.
4. `assemble.py` принимает Kokoro WAV и manifest без потери проверок.
5. Нет автоматического fallback на Piper.
6. Автоматические тесты проверяют успешный синтез, ошибки, повреждённые WAV, manifest и совместимость.
7. На Windows выполняется реальный TTS через основной CLI.
8. Создаётся полноценный MP4, выполняется FFprobe QC.
9. Пользователь прослушивает всю озвучку и просматривает итоговое видео.
10. Создаётся `THIRD_PARTY_LICENSES.md` на основании фактических production-зависимостей.

# A/B-проверка качества русской озвучки

**Версия:** 1.2  
**Дата:** 25.10.2026  
**Цель:** выбрать TTS по реальному звучанию и работоспособности на целевой Windows-машине; не считать успешное создание WAV доказательством пригодности для публикации.

**Статус обновлён 25.10.2026:** пользователь оценил Kokoro Dima на 3,5/5 и Piper Dmitri на 2,5/5; оба не проходят порог 4/5.

## 1. Текущий результат

- Piper 1.8.0 с голосом `ru_RU-dmitri-medium` запускается на целевой Windows-машине. Минимальный UTF-8 smoke-test создал WAV длительностью 6,699 с, но это подтверждает только разборчивость короткого текста.
- **Пользовательская оценка Piper Dmitri — 2,5/5.** Отмечены проглатывание окончаний, ошибки склонения чисел и частые неверные ударения. Производственное качество не принято.
- Kokoro-ru v2 Dima технически синтезировал четыре WAV: 87,13 с итогового аудио за 26,91 с инференса, суммарный RTF ≈0,309 (около 3,24× быстрее реального времени).
- **Пользовательская оценка Kokoro Dima — 3,5/5.** Тембр воспринимается немного детским; числа склоняются/произносятся неверно. Kokoro лучше из двух по общей оценке, но критерий проекта ≥4/5 не пройден.
- Эти оценки являются субъективной редакторской оценкой пользователя. Детальные независимые баллы разборчивости/ударений/пауз для каждого блока не выставлены отдельно. Окончательное производственное решение не принято.
- **Следующая проверка:** ручной эксперимент с числами, заранее записанными словами, уже дал положительный результат по сообщению пользователя. В текущем срезе добавлен ограниченный автоматический нормализатор `text_normalization.py` v0.2.0. Следом установить реальный `num2words` в обоих окружениях, перезапустить одинаковый benchmark, проверить normalized text и прослушать WAV. Критерий естественности ≥4/5 остаётся независимым.

## 2. Кандидаты

1. **Piper Dmitri** — контрольная точка: уже встроен в `video-farm`, но естественность не принята, а коммерческие права на конкретный голос остаются открытым вопросом.
2. **Kokoro-ru v2 Dima** — мужской голос для сопоставления с Piper. Модель не интегрирована; требуется отдельный изолированный тестовый скрипт/окружение.
3. **Kokoro-ru v2 Sveta** — необязательный дополнительный кандидат, если пол персонажа не является ограничением для выбранного канала.

В текущей карточке `zaakirio/kokoro-ru` заявлены 81,81 млн параметров, peak RAM 2,39 GB и 9,8x real-time на CPU ноутбука. Это заявления автора на конкретном оборудовании, а не гарантия скорости на процессоре проекта Intel Pentium N3700.

## 3. Общий тестовый материал

Для каждой модели использовать один и тот же связный русский сценарий объёмом 60–90 секунд. Он должен содержать:

- нейтральную объяснительную прозу с обычными паузами;
- дату, время, числа, десятичную дробь и проценты;
- английское имя технологии и несколько аббревиатур;
- перечень, двоеточие, тире, скобки и предложение с вопросительной интонацией;
- слова с потенциально неоднозначным ударением; для Kokoro критичные омографы дополнительно проверить с явной разметкой ударения, если стандартная G2P-обработка ошибается.

Использовать один сохранённый UTF-8 исходный текст. Не редактировать его между движками. Разрешается нормализация, без которой движок технически не может работать, но она должна быть сохранена и отмечена в отчёте.

## 4. Процедура

1. На Windows сохранить отдельную папку на каждого кандидата и не затирать предыдущие WAV.
2. Для Piper запускать текущий `video_farm.cli tts` после UTF-8 hotfix; затем отдельно повторить `data/piper_control_script.json`, чтобы проверить, исчезло ли прежнее бессвязное звучание.
3. Для Kokoro-ru v2 использовать отдельное тестовое окружение `.kokoro-venv`, не добавляя зависимости в основное `.venv`. Установка и первый inference теперь подтверждены на Python 3.13.14 / ONNX Runtime 1.31.0. Записывать ревизию модели и SHA-256 весов/voice pack для каждого прогона.
4. Записать WAV, длительность аудио, время синтеза, приблизительный коэффициент realtime, пиковое потребление RAM, предупреждения и нормализованный текст.
5. Прослушивать образцы без заранее заявленного имени модели, если возможно. После прослушивания заполнить оценки и только затем раскрыть названия.
6. Сохранить результат в `output/tts-benchmark/<run-id>/` и заполнить таблицу результатов в конце документа.

## 5. Критерии приёмки

Оценка каждой шкалы — от 1 (плохо) до 5 (отлично).

| Критерий | Условие |
|---|---|
| Естественность | Не ниже 4/5; нет явного впечатления роботизированной речи |
| Разборчивость | Не ниже 4/5; слова понятны при обычной громкости |
| Ударения и произношение | Не ниже 4/5; ошибки на критических именах/терминах должны быть исправимы |
| Паузы и пунктуация | Не ниже 4/5; нет случайных разрывов и сбивчивого темпа |
| Техническая стабильность | WAV валиден; длина не аномальна; процесс завершается без ошибки/OOM |
| Производительность | Время/RAM измерены на машине пользователя; решение принимается по практической приемлемости для его объёма выпуска |
| Права | Открытые существенные лицензионные вопросы должны быть закрыты отдельно перед публичной монетизацией |

**Отклонить** образец для производственного использования, если естественность ниже 4/5 или пользователь считает речь очевидно роботизированной, даже когда все слова разборчивы. Это внутренний критерий данного проекта, а не универсальный стандарт TTS.

## 7. Следующий эксперимент: преднормализованные числа

Файл `data/tts_numbers_prenormalized_script.json` содержит отдельный блок, в котором дата, время, проценты, температура, объём и стоимость записаны словами с нужными окончаниями. Пользователь сообщил, что числа начали звучать правильно. Это подтвердило смысл предварительной подготовки `voice_text`. В версии кода v0.2.1 был добавлен автоматический слой для явно поддержанных шаблонов и переведён на канонические коды падежей `num2words`; он ещё не проверен на Windows с настоящей зависимостью и не принят по реальному аудио.

Команды:

```powershell
.\.kokoro-venv\Scripts\python.exe -X utf8 .\tools\kokoro_onnx_benchmark.py --script data\tts_numbers_prenormalized_script.json --out output\kokoro-numbers-prenormalized --voice dima --threads 2
.\.venv\Scripts\python.exe -m video_farm.cli tts --script data\tts_numbers_prenormalized_script.json --out output\piper-numbers-prenormalized --speed 1.0
```

Результат по наблюдению пользователя: числа в заранее написанном словами сценарии стали звучать правильно. В автоматическом слое расширяем только явно поддерживаемые случаи: даты, время, проценты, известные единицы/валюты и несколько названий моделей. Неизвестные числовые шаблоны оставляются в тексте и должны вручную проверяться по `unconverted_numeric_tokens`. Это не решает детский тембр Kokoro и проглатывание окончаний/ошибки ударения Piper. Общие оценки сохраняются: Kokoro 3,5/5, Piper 2,5/5.

## 8. Техническое решение после A/B

- Если Kokoro показывает существенное преимущество по естественности и запускается на целевом компьютере без неприемлемых затрат ресурсов, продолжить его интеграцию в отдельной ветке/модуле.
- Если оба кандидата не проходят естественность, не заставлять их пройти за счёт косметической обработки; провести отдельный поиск модели с коммерчески допустимой лицензией и проверить права на голоса.
- Независимо от качества, не публиковать монетизируемые видео с голосом до закрытия соответствующего критического лицензионного вопроса.
- После выбора оформить ADR, обновить `DECISION_TTS.md` и SRS.

### Вывод и следующий эксперимент

1. Сохранять исходный редакторский `text` и отдельный `voice_text` для синтеза. Нормализатор меняет только текст, передаваемый TTS; текст слайда не заменяется.
2. Установить пакет `num2words` в рабочие окружения, затем проверить, что `doctor` показывает числовую нормализацию как готовую.
3. Проверить manifest: `source_voice_text`, `normalized_voice_text`, хеши, версию backend и `unconverted_numeric_tokens`. Если цифры остались, не считать нормализацию успешной автоматически.
4. Повторить полный benchmark на Kokoro и Piper и отдельно оценить естественность, окончания, ударения, числа и паузы. Пока общее качество не достигнет 4/5, производственная приёмка не закрыта.


## 11. Следующий gate: реальная нормализация `num2words` — 25.10.2026

В v0.2.1 вызовы `num2words` стандартизированы на коротких кодах падежей `n/g/d/a/i/p`. Исходный код версии 0.5.14 также поддерживает английские aliases, поэтому это стандартизация API, а не доказательство ранее происходившего сбоя. Тестовые double теперь тоже используют коды библиотеки, а новый integration test проверяет фактические результаты при установленном `num2words`.

В контейнере `num2words` не установлен из-за отсутствия доступа к PyPI; после добавления v0.2.2 последняя проверка дала `33 passed, 1 skipped`. Это не подтверждает реальную работу библиотеки. На Windows выполнить команды из `docs/10_windows_normalizer_validation.md`, изучить `normalized_voice_text` и `unconverted_numeric_tokens`, прослушать WAV и заполнить новый пользовательский рейтинг. Рейтинги TTS не повышать без новой оценки естественности; порог приёмки остаётся 4/5.


## Актуализация 26.10.2026 — исправление родовых форм

Пользователь сообщил, что вывод `normalize_for_speech` после установки настоящего `num2words 0.5.14` не всегда грамматически корректен. Исследуя код v0.2.1, обнаружен конкретный крайний случай: числительные перед женскими единицами не получали женский род (`2 минуты` могло стать `два минуты`; время `14:02` — `четырнадцать часов два минуты`). Кроме того, глобальная замена `—`/`–` на запятые ухудшала синтаксис фразы.

В нормализатор v0.2.2 внесены изменения: женские формы для минут/секунд/миллисекунд, женская форма минут в записях времени, сохранение тире. Добавлены тесты. Контейнер: 33 passed, 1 skipped; настоящий `num2words` отсутствует в контейнере. Эти изменения не считаются принятыми, пока пользователь не выполнит тест v0.2.2 на Windows и не прослушает аудио.

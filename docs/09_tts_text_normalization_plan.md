# План разработки подготовки текста для TTS (voice_text)

**Дата:** 26.10.2026  
**Статус:** v0.2.2 подготовлен; реальный `num2words 0.5.14` был использован на Windows с v0.2.1, где пользователь обнаружил недочёты склонения. В v0.2.2 добавлена родовая форма для женских единиц и сохранение тире; этот патч ожидает Windows-проверки и WAV.

## Наблюдение

Пользователь сообщил, что числа начали звучать правильно в изолированном сценарии, где дата, время, проценты, температура, размер файла и стоимость уже были написаны словами с согласованными окончаниями. Это показывает ценность отдельного произносимого текста. Это не означает, что автоматически решено произношение любых чисел в свободном русском тексте. В первой реализации поддерживаются только описанные ниже шаблоны; произвольные цифры не преобразуются наугад.

## Требование к модели данных

- `text` — исходный редакторский текст; используется для визуальных материалов/отображения.
- `voice_text` — текст, специально подготовленный для озвучки; синтезатор получает именно его, когда поле присутствует.
- Не заменять и не терять исходный текст при нормализации.
- Преобразования должны быть детерминированными, тестируемыми и отражаться в аудио-манифесте (версия нормализатора и хеш итогового voice_text).
- Если падеж/род/число нельзя надёжно определить локальным правилом, оставить объект на ручную правку, не угадывать молча.

## Приоритеты реализации

1. Даты: «25 октября 2026 года» → словесная форма с падежом и годом.
2. Время: «14:35» → словесная форма, различать контекст времени суток при необходимости.
3. Проценты и десятичные числа: «3,7%» → «три целых семь десятых процента» в правильной форме.
4. Температура и единицы измерения: «21,5 °C», «1 ГБ 250 МБ».
5. Валюта: «4500 ₽» → «четыре тысячи пятьсот рублей»; падеж определяется окружающей конструкцией.
6. Порядковые числительные, диапазоны, номера и аббревиатуры — только с явными тестами; не считать универсально решёнными.

## Тестовые требования

- Сохранять для каждого теста исходный `text`, ожидаемый `voice_text` и краткое объяснение грамматической формы.
- Проверять воспроизводимость результата и отсутствие непреднамеренного изменения числа/единицы.
- Синтезировать `voice_text` через Kokoro и Piper, прослушать числа/окончания и независимо оценить тембр, естественность, ударения и паузы.
- Регрессионный benchmark содержит нейтральную связную речь, даты/числа, термины и пунктуацию.
- Не принимать TTS по качеству, если общий балл ниже 4/5, даже при правильных числах.

## Ограничения и безопасный fallback

Первая версия должна покрывать явно заявленные шаблоны, а не претендовать на полную морфологическую генерацию для русского языка. Для сложных/неоднозначных конструкций использовать редакторское поле `voice_text` и помечать необходимость ручной проверки.


## Что реализовано в v0.2.0

- Модуль `src/video_farm/text_normalization.py`, версия `0.2.2`.
- Явные шаблоны: цифровые и частично словесные даты; времена `HH:MM`; проценты; рубли/доллары; распространённые единицы (градусы, GB/ГБ, MB/МБ, TB/ТБ, KB/КБ, секунды/минуты/миллисекунды); некоторые идентификаторы моделей.
- Известные единицы и валюты склоняются по числовому значению в покрытых случаях.
- Любой оставшийся числовой токен не преобразуется общей эвристикой: он сохраняется и заносится в `unconverted_numeric_tokens`/`quality_warnings` для ручной проверки. Это намеренный fail-safe, чтобы не порождать неверный падеж молча.
- Piper-манифест хранит `source_voice_text`, `normalized_voice_text`, хеши обоих вариантов, версию нормализатора, backend и нераспознанные числовые токены. Kokoro benchmark тоже записывает хеш исходного и нормализованного текста.
- Зависимость `num2words>=0.5.14,<0.6` включена в extras `[tts]` и `[test]`. `doctor` выводит её статус. В среде разработки без доступа к PyPI настоящая библиотека не установлена; текущий контейнерный запуск v0.2.2: 33 passed, 1 skipped. Коды падежей стандартизированы на `n/g/d/a/i/p`, поддерживаемые русской локалью `num2words`; реальный API-тест должен выполниться в Windows после установки зависимости.

## Следующий шаг после реализации

1. В Windows выполнить `python -m pip install -e ".[tts,test]"` в `.venv`, затем проверить `doctor` и integration test.
2. Для Kokoro отдельно установить `num2words>=0.5.14,<0.6` в `.kokoro-venv`.
3. Повторить benchmark обоими движками. Убедиться, что ключевые конструкции заменены в манифесте правильно, а нераспознанные токены явно выведены в предупреждения.
4. Выполнить `docs/10_windows_normalizer_validation.md`: проверить оба manifest и прослушать WAV, внести ручные корректировки в `voice_text` там, где склонение неоднозначно. Не менять оценки Kokoro/Piper до нового полноценного A/B.

## Критерий завершения

- Реализован модуль нормализации с фиксированной версией и unit-тестами.
- Оригинальный `text` не теряется; `voice_text` сохраняется в manifest.
- Все тестовые пары проходят, затем полный контрольный сценарий синтезирован обоими TTS.
- Результаты ручного прослушивания записаны; производственный голос всё равно требует ≥4/5 и закрытого лицензионного вопроса.


## Версия v0.2.1 — канонизация кодов падежей

По документации и исходному коду `num2words 0.5.14`, русская локаль принимает коды `n`, `g`, `d`, `a`, `i`, `p`, а также английские aliases. Нормализатор теперь канонически преобразует внутренние полные названия падежей в краткие коды. Моки используют этот единый формат. Документация и код версии 0.5.14: <https://github.com/savoirfairelinux/num2words/blob/v0.5.14/num2words/lang_RU.py>. Добавлен интеграционный тест, который выполняется, когда настоящая зависимость установлена. В текущем container-окружении тест пропущен; Windows runtime + WAV всё ещё не приняты.


## Версия v0.2.2 — родовой контроль известных единиц

- Обнаружен дефект в числе перед существительными женского рода: для `1 минута`, `2 минуты`, `21 секунда`, `22 секунды` и времени `14:02` форма числительного должна быть женской (`одна`, `две`, `двадцать одна`, `двадцать две`).
- `_unit_replacement` теперь передаёт `gender="f"` для минут, секунд и миллисекунд, `gender="m"` для мужских единиц; для десятичных дробей не навязывает род единицы, поскольку дробная форма строится через `целая/десятых`. В `_clock_replacement` часы получают мужской род, минуты — женский.
- Убрана глобальная замена тире запятой, которая меняла пунктуацию и могла портить фразу (`Температура — ...`).
- Добавлены регрессионные тесты на женские/мужские единицы, время `14:01`, `14:02` и тире. Контейнер: 33 passed, 1 skipped; пропущен интеграционный тест, поскольку в контейнере отсутствует настоящий пакет `num2words`.
- **Не закрыто:** повторный запуск v0.2.2 на Windows с настоящим `num2words`, проверка вывода и синтеза WAV. Это не полный морфологический анализ русского языка: для неоднозначной грамматики по-прежнему необходим явный `voice_text` или ручная корректировка.

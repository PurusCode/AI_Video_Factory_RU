# AI Video Factory RU — Trend Discovery, Stage 1

Дата подготовки: 2026-11-02  
Статус: первая реализация, требует live-проверки на Windows с действующим `YOUTUBE_API_KEY`.

## Цель

Ежедневно получать кандидатов для выбора пользователем на основе недавних видео YouTube, используя только исходные поля YouTube Data API v3. На этом этапе программа не делает вывод, что ролик «вирусный» или быстрорастущий: для этого требуются временные измерения и собственные производные метрики.

## Поведение первой версии

Команда:

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli discover --out output/discovery
```

Параметры:

- `--query` — OR-запрос для YouTube search.list; по умолчанию фокус AI/нейросети/LLM.
- `--region RU` — регион доступности видео.
- `--language ru` — языковой приоритет результатов, не строгий фильтр языка.
- `--max-results 50` — максимум 50 элементов на отдельный запрос.
- `--out output/discovery` — каталог, в котором перезаписываются `discovery.json` и `discovery.md`.

Для каждого из временных окон 1, 3 и 7 дней делаются отдельные `search.list` запросы с сортировками `viewCount`, `date`, `relevance`. Каждая выдача сохраняется как отдельный набор; результаты не объединяются между окнами и сортировками. По каждому набору сведения о видео обогащаются полями `videos.list` для тех же video IDs.

## Что отображается

Только поля, возвращённые API: заголовок, канал, дата публикации, число просмотров, лайков и комментариев (когда поля доступны), длительность ISO 8601, категория и ссылка. Сортировка выдачи сохраняется от API.

## Что намеренно не реализовано

- скорость роста просмотров / просмотры в час;
- `viral_ratio`, трендовый индекс или иной собственный score;
- медианы и сравнение каналов;
- агрегирование статистики по нескольким каналам;
- автоматическое объединение роликов в темы / теги по содержимому API;
- автоматическое скачивание аудио/видео референса.

Для дополнительных производных метрик YouTube указывает необходимость явного применения и одобрения аналитического use case; простая установка флага или соглашение в форме не гарантирует одобрения. Пока такого разрешения нет, первая версия даёт исходные списки кандидатов, а решение о теме остаётся за пользователем.

## Квота

На полный прогон: 9 `search.list` запросов (отдельная Search Queries quota, по 1 единице на запрос) и до 9 `videos.list` запросов (стандартная квота, по 1 единице на запрос). Страницы `nextPageToken` не запрашиваются.

## Ограничения поиска

Документация YouTube указывает, что сортировка не по `relevance`, особенно вместе с `publishedAfter`/`publishedBefore`, может возвращать неполный набор. Поэтому три режима выводятся раздельно, но результат всё равно не следует называть полным рейтингом YouTube.

`regionCode` — регион, где видео доступно для просмотра, а не местонахождение автора. `relevanceLanguage` лишь задаёт приоритет языка; результаты на иных языках всё ещё могут попадать в выдачу.

## Хранение данных

Отчёт одинарный и перезаписывается следующим запуском. В JSON записано поле `refresh_or_delete_by_utc` на 30 дней после выгрузки. Это ещё не полноценный автоматический механизм очистки: до регулярного запуска необходимо добавить/настроить ежедневную задачу удаления или обновления отчёта, в том числе на случай, если discovery долго не запускается.

## Очистка старого отчёта

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli discover-cleanup --out output/discovery
```

Команда удаляет только `discovery.json` и `discovery.md` из указанного каталога и только после срока `refresh_or_delete_by_utc`. Повреждённый или неполный JSON оставляется для ручной проверки.

- проверка CLI `discover --help`;

# План работ AI Video Factory RU / video-farm

**Версия:** 1.6 — этап 3: нормализатор voice_text v0.2.2, родовой regression gate  
**Дата:** 16.10.2026

## Текущая рабочая база

Для текущего продолжения используется папка/архив `video-farm`, потому что в ней находится интеграция Piper, которую проверял пользователь. Отдельный архив `AI_Video_Factory_RU` с Streamlit — параллельный прототип и не считается частью этой ветки, пока код явно не объединён и не протестирован.

## Этап 1 — исследование

Есть первичные материалы по российскому законодательству, API платформ, провайдерам, лицензиям и бюджету. До добавления новых интеграций проверять актуальные правила по первоисточникам. Монетизация, выплаты, рекламные интеграции и ERID/ОРД отложены до достижения порогов аудитории; контентные ограничения и права на материалы обязательны с первого ролика.

## Этап 2 — архитектура

Зафиксирована CLI-архитектура на Python: YouTube API / ручная тема → сценарий → TTS → стоки и манифест → PNG-слайды → FFmpeg → FFprobe QC → ручная редакторская проверка → материалы для ручной публикации. Piper — текущая реализация TTS, однако производственный голос не принят. Kokoro-ru v2 не интегрирован, но рассматривается как кандидат после юридической и технической проверки. Подробный статус требований — `docs/01_SRS.md`. Документ не объявляет функции готовыми лишь потому, что они описаны.

## Этап 3 — проверить и довести MVP

### Приоритет A: воспроизводимая озвучка и видео

1. Выполнить `doctor` на целевом Windows-компьютере.
2. В `.venv` выполнить `python -m pip install -e ".[tts,test]"`; в `.kokoro-venv` установить `num2words>=0.5.14,<0.6`. Запустить интеграционный тест, проверить нормализованные тексты/манифесты и повторно синтезировать контрольный benchmark обоими движками.
3. Проверить, что все блоки сценария получают корректные WAV и одинаково отражены в manifest.
4. Выполнить полный цикл по готовому сценарию — сначала `--draft`, затем полный рендер.
5. Просмотреть MP4 и прослушать всю речь; проверить фактические длительность, кадр/частоту, аудио и QC.

### Приоритет B: бюджет и конфигурация LLM

1. По умолчанию оставлять локальный Ollama, если он даёт приемлемое качество/скорость.
2. Для удалённого endpoint до первого запроса подтвердить доступность и оплату из РФ, коммерческие условия, требования по раскрытию ИИ и фактическую совместимость API.
3. Ввести реальный budget gate до сетевого вызова и учёт повторных запросов. Не полагаться на фиксированную оценку, если стоимость неизвестна.
4. Сверить расчёт с кабинетом поставщика после одного контролируемого вызова.

### Приоритет C: права и качество

1. Проверить все факты и источники сценария вручную.
2. Зафиксировать точную лицензию движка Piper и зависимости.
3. **Коммерческий блокер:** получить письменное подтверждение прав на голоса `dmitri`/`denis` (оба fine-tuned from Lessac, лицензия исходных Materials ограничивает использование research-only) либо выбрать модель с однозначными правами на коммерческий синтез. См. `docs/06_piper_licensing_audit.md`.
3. Проверить каждый скачанный B-roll/фото и корректность атрибуции.
4. Блокировать публикацию, если источники/права неизвестны или описательная атрибуция не соответствует фактически использованным медиа.

### Приоритет D: соответствие обязательным требованиям ТЗ

1. Реализовать вертикальный 9:16, если он по-прежнему обязателен; текущий рендер в архиве ориентирован на 1920×1080 (16:9).
2. Определиться, нужна ли Streamlit-панель. Не считать панель из другого архива частью `video-farm` без отдельного переноса.
3. Добавить тесты для отказов загрузки Piper/модели, отсутствующих API ключей, неполного набора WAV, отсутствующих лицензий и невалидного QC.
4. Провести резервное копирование/восстановление.

### Зафиксированный прогресс по этапу 3 — 16.10.2026

- **Закрыто на уровне архитектуры:** активная ветка — `video-farm` CLI с Piper; отдельный Streamlit-прототип исключён из этого репозитория и отчётов.
- **Реализовано в коде:** TTS-манифест записывает статус синтеза, версию Python/ОС, версию `piper-tts`, SHA-256 модели/конфигурации, параметры WAV, исходный `voice_text`, нормализованный `voice_text`, их хеши, версию/back-end нормализатора и оставшиеся числовые токены. Частичный/неудачный прогон сохраняет статус `failed`.
- **Реализовано в коде:** проверяются пустые/дублирующиеся блоки, допустимая скорость, корректность WAV и соответствие частоты дискретизации конфигурации голоса. Смена голоса без своей пары URL модели и конфигурации больше не скачивает модель Дмитрия под другим именем.
- **Реализовано в коде:** сборка MP4 прекращается при неполном или устаревшем аудиоманифесте, отсутствующем/повреждённом WAV, несовпадении длительности WAV и манифеста, а также при отсутствии слайдов для блока. Пропустить блок и молча собрать несинхронный ролик нельзя.
- **Реализовано в коде:** `*.qc.json` записывает реально использованные стоковые файлы; описание публикации формирует атрибуцию по этим данным. Когда сборки ещё нет или список использования неизвестен, описание помечается как требующее ручной сверки; при отсутствии внешних материалов Pexels/Pixabay не приписываются.
- **Добавлено:** контрольный сценарий `data/piper_control_script.json` и команды для запуска, инструкция находится в README.
- **Автотесты (v0.2.2 в контейнере):** `PYTHONPATH=src python -m pytest -q -rs` — 33 passed, 1 skipped; TTS синтез проверяется mock Piper, тесты числовой нормализации используют mock-конвертер. Интеграционный тест реального `num2words` пропущен, потому что пакет отсутствует в контейнере.
- **Smoke-test конвейера:** из 7 синтетических WAV созданы 21 PNG-слайд и черновой MP4 1280×720 с H.264/AAC; FFprobe прочитал файл. Это проверка сборки, а не публикационное видео.
- **Не закрыто:** настоящий `num2words` не установлен в текущем container-окружении. В v0.2.1 вызовы стандартизированы на короткие коды русских падежей, но фактическое выполнение ещё не подтверждено с библиотекой. Настоящий `num2words 0.5.14` был запущен на Windows для версии v0.2.1, но обнаружены некорректные варианты для женских единиц и глобальная замена тире. Проверить патч v0.2.2, выполнить `tests\test_text_normalization.py`, проверить ожидаемые фразы и повторить benchmark обоими движками. Полный реальный рендер и ручной просмотр/прослушивание остаются обязательными.

## Этап 4 — пилотный контент

Плановый профиль: тестировать образование, технологии/ИИ, историю и науку; максимум две темы на нишу. Текущая сборка исторически ориентирована на технологические видео, поэтому адаптация сценариев/источников под остальные ниши должна быть оценена. Сначала подготовить несколько тестов, затем выбрать не более 1–2 перспективных направлений по качеству, оригинальности, стоимости и возможности регулярного производства. Не обещать просмотры или доход.

## Этапы, отложенные до подтверждения необходимости

- Автоматическая загрузка в VK Видео/RUTUBE — только после подтверждения официального доступа, прав и отдельной реализации human approval gate.
- Комментарии — после отдельной проверки API и персональных данных.
- Мультиканальность и расписание — после результатов пилота.
- Монетизация и налоговые процедуры — ближе к порогам каналов, но до фактических выплат.
- Сервер/очереди/масштабирование — только после того, как локальный процесс подтверждён.

## Критерии готовности MVP

- [ ] Piper TTS проходит тест на целевой машине, сохранены версия и контрольный результат.
- [ ] Полный сквозной ролик создан с реальной озвучкой и вручную проверен.
- [ ] Рендер проверен FFprobe и просмотром/прослушиванием.
- [ ] Использованные медиа внесены в манифест, лицензии проверены.
- [ ] До коммерческой публикации получено подтверждение лицензии голоса/аудиовыхода; голос с неразрешённой цепочкой прав не используется в монетизируемом контенте.
- [ ] Бюджет блокирует платный шаг заранее и журналирует фактические оценки.
- [ ] LLM-провайдер и способ оплаты подтверждены для конкретного аккаунта.
- [ ] Публикация/монетизация/комментарии не происходят автоматически.
- [ ] Резервная копия проверена восстановлением.

### Стандартизация аргумента падежа num2words — 25.10.2026

Нормализатор v0.2.2 теперь передаёт падежи в каноническом коротком формате `n/g/d/a/i/p`. В `num2words 0.5.14` поддерживаются также английские aliases (`nominative`, `genitive` и другие), поэтому прежний вариант не считаем доказанной причиной сбоя. Моки используют канонический формат; добавлен integration test на настоящую зависимость. В локальном контейнере итог — 30 passed, 1 skipped; пропуск связан с отсутствующим `num2words`. Этап не закрыт до Windows-проверки.


### Актуализация 26.10.2026 — v0.2.2 нормализатора

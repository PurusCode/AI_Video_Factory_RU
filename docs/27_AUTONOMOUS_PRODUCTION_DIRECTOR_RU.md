# Автономный AI-режиссёр и production-конвейер

Основа overlay: AI Video Factory RU, `main` на `4454e27`.

## Полный цикл

1. При `--script` ферма сама создаёт семантическую раскадровку существующим storyboard-модулем. При `--storyboard` использует готовую семантическую раскадровку.
2. AI-режиссёр строит визуальный план. Каждый visual beat содержит точный непрерывный `spoken_text` — часть исходного `voice_text`, а также визуал/адаптер.
3. Детерминированная проверка требует, чтобы склейка всех `spoken_text` совпала с исходной речью. Пропуски, перестановки и перефразирование блокируют план.
4. Независимая AI-критика проверяет соответствие речи, реализуемость, разнообразие и риск выдуманных данных. До двух циклов автоматического исправления.
5. Источники: ферма получает текст открытых страниц и просит AI сопоставить его с claim. Доступность URL не является подтверждением факта; даже `supports` остаётся кандидатом и требует человеческой проверки. Никакие claims не получают `verified` автоматически.
6. Kokoro Dima синтезирует каждый точный spoken beat в отдельный WAV. Длительность визуала равна измеренной длительности соответствующего WAV, а не выдуманному ratio.
7. Визуалы создаются локальным Pillow renderer или скачиваются через существующий Pixabay adapter. Если Pixabay не дал материал, применяется локальный визуальный fallback и это попадает в warnings.
8. В renderer 1.1.0 `visual_description` строго остаётся внутренней инструкцией и не выводится как текст. Видимые надписи берутся из `on_screen_text`, проходят фильтр на фразы-инструкции и ограничение длины. Добавлены шаблоны comparison, process flow, kinetic typography, simulated interface, editorial quote, visual punchline и семантические иллюстрации (browser/search/phone/database/network/warning/shield/tokens).
9. После создания исходных assets запускается `visual_asset_audit.json`: проверка декодирования, минимального размера, sidecar-метаданных, утечки внутреннего описания, instruction-like display copy, близких дублей по perceptual hash и трёх одинаковых типов визуала подряд. После FFmpeg-сборки `visual_audit.json` извлекает репрезентативный кадр из каждой фразы непосредственно из закодированного `final.mp4`; `visual_contact_sheet.jpg` строится именно по этим финальным кадрам, включая overlays/crop/encoding. Ошибки двух аудитов попадают в postproduction QC.
10. Оригинальные процедурные SFX и тихий ambient pad генерируются локально; это не коммерческий саундтрек и не сторонняя музыка.
11. FFmpeg собирает видео и аудио, затем проверяются реальная длительность, потоки, наличие файлов и непрерывность beat timeline.


## Установка

Архив — additive overlay: он не перезаписывает старые модули, `.env`, модели, `data/` и `output/`.

1. Распакуйте содержимое архива в корень `video-farm` с сохранением структуры папок.
2. В PowerShell из корня репозитория выполните:

```powershell
powershell -ExecutionPolicy Bypass -File .\install_director_overlay.ps1
```

Скрипт проверит наличие новых файлов, выполнит `pip install -e . --no-deps` (без обновления зависимостей), запустит полный набор `pytest tests -q` и проверит CLI. Можно выполнить эти команды вручную, если предпочитаешь контролировать каждый шаг.

Новые зависимости не добавляются: используются уже имеющиеся Pydantic, Pillow, NumPy, Requests и модули проекта.

## Границы и честные гарантии

- Точная временная привязка обеспечивается на уровне фраз/предложений: каждый фрагмент речи имеет свой Kokoro WAV и визуальный клип. Это не forced alignment до отдельного слова/фонемы.
- Независимая критика — отдельный структурированный вызов с иной ролью. По умолчанию используется обычный порядок провайдеров проекта (MWS → Ollama). Для отдельного critic-провайдера можно задать `DIRECTOR_CRITIC_PROVIDER=secondary` (или `primary`) в `.env`; `auto` оставляет штатный порядок. Установщик `.env` не меняет.
- AI-оценка источника не является окончательным фактчекингом; для публикации человек должен проверить claim, первоисточник, дату и контекст.
- Внутренний renderer — процедурная 2D-графика, а не генератор кинематографического видео. Он использует специализированные композиции, но не обещает произвольные частицы/3D/реальный интерфейс. UI-кадры явно маркируются как учебная симуляция.
- Звук — тихий оригинальный процедурный фон и короткие эффекты, а не полноценная музыкальная композиция.
- Visual audit автоматически проверяет физическую пригодность кадров, повторения и содержимое sidecar-метаданных, но не использует OCR и не доказывает, что кадр семантически соответствует речи. Для этого нужен просмотр contact sheet и MP4.
- `visual_description` запрещено выводить в кадр. В кадре разрешены только короткие `on_screen_text`, заголовок, построенный из смысла сцены/речи, и подписи самого шаблона.
- Версия 1.1.0 не добавляет новые зависимости и не меняет старый pipeline или `.env`. Для повторного пилота используй отдельный пустой `--out`, чтобы сгенерировать новый план с обновлёнными инструкциями renderer.
- `manual` и `generated` стратегии/провайдеры запрещены. `screencast` как реальная запись не поддерживается; допустим только визуальный тип `screencast`, который создаётся локально как явно маркированная учебная симуляция интерфейса.
- Права на внешние Pixabay-файлы и все фактические утверждения остаются предметом проверки перед публикацией.


## Изменения overlay 1.1.0

Renderer использует отдельные семантические композиции и сохраняет рядом с PNG файл `.meta.json` с template ID и фактически разрешённым видимым текстом. Внутреннее описание режиссёра в изображение не передаётся. `visual_asset_audit.json` проверяет исходные assets и metadata; `visual_audit.json` извлекает кадры из самого MP4 и строит по ним `visual_contact_sheet.jpg`. Оба результата включаются в `postproduction_qc.json`. Это не автоматический semantic vision critic: человеческий просмотр обязателен.

## Исправление overlay 1.0.1

Микшер ambient pad округляет число отсчётов до ближайшего целого и ограничивает
конечный индекс фактической длиной мастер-озвучки. Это предотвращает ошибку
NumPy при сложении массивов, когда округление секунд давало разницу в один
сэмпл. Регрессионные тесты проверяют точную длину pad и сохранение количества
сэмплов итогового WAV на дробной длительности.

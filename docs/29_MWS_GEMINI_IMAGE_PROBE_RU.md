# MWS `gemini-3.1-flash-image` — одноразовый тест генерации

## Что известно по официальной документации

- MWS перечисляет `gemini-3.1-flash-image` среди прокси-моделей Google с входом `Text, Image` и выходом `Text, Image`.
- MWS сообщает, что прокси-модели обслуживаются внешними провайдерами: GPT Model Hub передаёт им запрос.
- MWS OpenAI-совместимые инструкции подробно показывают Chat Completions и Responses, включая передачу картинки **на вход**, но в опубликованных примерах не дают подтверждённого запроса для генерации изображения **на выход**.
- Поэтому `POST /images/generations` тестируется как гипотеза совместимости OpenAI Image API. Успех или ошибка должны быть зафиксированы до интеграции в production.

## Запуск

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -X utf8 .\tools\mws_image_probe.py
```

Скрипт читает `LLM_PRIMARY_BASE_URL` и `LLM_PRIMARY_API_KEY` из текущего `.env` (либо из переменных среды). Он не выводит ключ и не меняет `.env`.

Отправляется ровно один запрос:

```text
POST {LLM_PRIMARY_BASE_URL}/images/generations
model = gemini-3.1-flash-image
n = 1
```

Не запускайте команду многократно без анализа предыдущего результата: каждый успешный вызов может быть платным.

## Результаты

Папка по умолчанию:

```text
output\diagnostics\mws-gemini-image\
```

Файлы:

- `generated_image.png` (или соответствующее расширение), если изображение извлечено и валидировано Pillow;
- `probe_report.json` — endpoint, статус, время, наличие изображения, размеры и доступные поля usage;
- `response_sanitized.json.txt` — тело ответа без API-ключа для диагностики формата.

## Как интерпретировать

- `image_generated_and_validated`: API вернуло валидную картинку. Это подтверждает совместимость выбранного endpoint и response parser.
- `api_error` с HTTP 404/405: маршрут не поддерживается; это не доказывает, что модель недоступна.
- `api_error` с HTTP 400/422: вероятно, endpoint распознан, но формат запроса/модель/параметры не подходят. Сохранённый текст ошибки нужен для следующего шага.
- `http_ok_but_no_recognized_image_payload`: запрос принят, но схема ответа отличается от известных форматов; нужно расширить parser, не повторяя генерацию.
- `invalid_image`: API прислало данные, которые не являются корректным изображением или имеют слишком низкое разрешение.

Не передавайте файлы `response_sanitized.json.txt` публично: они не содержат ключ, но могут включать текст ответа провайдера и метаданные запроса.

# Hotfix: нечитаемая речь Piper в Windows

Дата: 2026-10-16

## Наблюдение

При вызове `piper.exe` из Python-процесса `video-farm` передача кириллического текста через stdin могла приводить к неверному декодированию в дочернем Python-процессе Windows. Кодировал входной текст в UTF-8 родительский процесс, но кодировка stdin в дочернем процессе могла оставаться системной ANSI-кодировкой. Результатом могли быть бессмысленные аудио-фрагменты при формально успешном создании WAV.

Это наиболее вероятная причина описанного симптома; её нужно подтвердить повторным прослушиванием после хотфикса. Файл `manifest.json`, прочитанный в Windows PowerShell 5.1 без `-Encoding utf8`, также может показывать русские строки нечитаемыми из-за способа отображения UTF-8 без BOM. Само по себе это не доказывает повреждение JSON.

## Исправление

Перед запуском Piper задаются переменные дочернего процесса:

- `PYTHONUTF8=1`
- `PYTHONIOENCODING=utf-8`

Команда синтеза по-прежнему передаёт строку из Python как UTF-8. Для качества добавлены предупреждения, когда длительность блока превышает 1,5 секунды на распознанное слово. Это диагностическое предупреждение, а не универсальное правило для всех сценариев.

## Проверка

- `python -m compileall -q src tests` — успешно.
- `PYTHONPATH=src python -m pytest -q` — 23 теста пройдены.
- Автоматические тесты проверяют, что дочернему Piper передаётся UTF-8-окружение, но используют имитацию Piper. Реальное качество звука нужно подтвердить на Windows после применения хотфикса.

## Применение в Windows

Заменить файл `src\video_farm\tts.py` на версию из этого архива. Затем повторить `tts` для контрольного сценария. Для отображения русских строк манифеста в Windows PowerShell использовать `Get-Content -Encoding utf8 -Raw ...`.


## Реальная проверка на Windows — 25.10.2026

- Подтверждён `piper-tts==1.8.0` в `.venv`; команда `piper` разрешилась в `video-farm\.venv\Scripts\piper.EXE`, голос Dmitri уже в кэше.
- Smoke-test одной обычной русскоязычной фразы создал WAV длительностью 6.699 с. Manifest зафиксировал `stdin_encoding=UTF-8`, `child_python_utf8_mode=true`, `quality_warnings=[]`. Sample прослушан: речь разборчивая.
- Это подтверждает передачу обычного UTF-8 текста, но не закрывает первоначальную проблему с четырёхблочным тестом, содержащим числа, английские термины, аббревиатуры и пунктуацию. Повторить этот сценарий в новом output-каталоге.


## Дополнение 25.10.2026 — естественность отдельно не принята

После подтверждения минимального русского smoke-test пользователь отметил, что другой фрагмент Piper (`01_russian_phonetics.wav`) звучит явно синтетически и недостаточно естественно. Это не опровергает передачу UTF-8, но означает, что исправление кодировки нельзя считать решением общей проблемы качества озвучки. Требуется отдельный сравнительный тест Piper/Kokoro на одинаковом тексте; см. `docs/08_tts_quality_benchmark.md`. Точный запуск, породивший приложенный фрагмент, не связан с манифестом, поэтому его не идентифицируем как прогон после hotfix.

# AI Video Factory RU / video-farm — SRS

**Документ:** Software Requirements Specification (SRS) / спецификация требований к системе  
**Версия:** 0.9 (подтверждена работа num2words на Windows; исправлена обработка рода для единиц женского рода и сохранение тире; приёмка патча на Windows ожидается)  
**Актуальность статусов:** 26.10.2026; пользователь установил num2words 0.5.14 в .venv и .kokoro-venv и выполнил автоматическую нормализацию на Windows. Выявлены пропущенные случаи согласования рода для женских единиц (например, «два минуты») и нежелательная замена тире запятой. В нормализатор v0.2.2 внесены исправления и новые регрессионные тесты; патч ещё нужно проверить на Windows с реальной зависимостью и WAV.  
**Состояние документа:** рабочая базовая версия; проект ещё не принят как готовый к регулярному производству.  
**Единственная текущая кодовая ветка в области этого SRS:** CLI-проект `video-farm`.

> **Правило достоверности:** наличие функции в коде, прохождение unit-тестов, успешное создание файла и пригодность результата для публикации — разные уровни доказательства. В этом документе они не смешиваются. Статус `РЕАЛИЗОВАНО, НЕ ПРИНЯТО` означает, что код/артефакты существуют, но критерий качества ещё не подтверждён.

## 1. Назначение и цель

Система предназначена для локальной подготовки оригинальных русскоязычных видео с помощью автоматизированного конвейера: выбор темы, сбор исследовательских данных, сценарий, озвучка, визуальные материалы, слайды, монтаж, технический контроль и комплект для ручной публикации.

Главная цель MVP — обеспечить повторяемое создание ролика с проверяемыми источниками и правами на использованные материалы, а не автоматизировать рост аудитории или гарантировать просмотры/доход.

## 2. Целевая эксплуатация

- Оператор: один владелец проекта, который вручную принимает редакторские и публикационные решения.
- Язык роликов: русский.
- Планируемые площадки публикации: VK Видео и RUTUBE.
- YouTube: только источник исследования трендов, не площадка публикации в текущем MVP.
- Плановые тестовые ниши: образование, технологии/ИИ, история, наука; не более двух тем на каждую нишу на первичном пилоте. После сравнения качества и затрат выбрать не более 1–2 направлений.
- Тип запуска: локальный CLI на Windows; публикация вручную после проверки человеком.

## 3. Область MVP

### 3.1. В область MVP входят

1. Анализ поисковых запросов и публичной статистики YouTube через официальный API, когда настроен ключ; либо ручной выбор темы.
2. Подготовка сценария в JSON и выделение блоков озвучки.
3. Синтез отдельных WAV по блокам с манифестом параметров и контрольных сумм.
4. Поиск/загрузка визуальных материалов через разрешённые API при наличии ключей и сохранение манифеста источников.
5. Создание PNG-слайдов.
6. Сборка MP4 посредством FFmpeg и техническая проверка через FFprobe.
7. Комплект материалов для ручной публикации: описание, хэштеги, источники и предупреждения QC.
8. Явные ошибки и блокировка сборки при отсутствующих/некорректных обязательных аудиофайлах, манифестах или слайдах.
9. Финальное ручное прослушивание, просмотр, фактчекинг и юридическая проверка владельцем канала.

### 3.2. Вне области текущего MVP

- Автоматическая загрузка роликов в VK Видео/RUTUBE, планирование публикаций через закрытые/неподтверждённые интерфейсы и автоматические ответы на комментарии.
- Автоматизация подключения монетизации, выплат, налоговой отчётности, рекламных интеграций и ERID/ОРД. Эти вопросы исследуются заново ближе к достижению актуальных порогов площадок; применимые требования к правам и законности контента обязательны с первой публикации.
- Собственные спонсорские интеграции, партнёрские ссылки и продажа товаров/услуг.
- Обязательная Streamlit-панель, SQLite-журнал бюджетов и UI из отдельного прототипа. Ничто из этого не считается реализованным в CLI-ветке без переноса и повторных тестов.
- Вертикальный рендер 9:16 — требование, которое необходимо подтвердить и реализовать до пилота, если формат остаётся обязательным. В имеющейся реализации основной профиль горизонтальный 1920×1080 (16:9).

## 4. Среда и ограничения

- Целевая ОС: Windows 10/11 x64; на машине владельца проверялась Windows 10, Python 3.13.14 x64.
- Python проекта: 3.12 или 3.13 x64; целевая машина сейчас использует 3.13.14.
- FFmpeg и FFprobe должны быть доступны через `PATH`.
- Локальный TTS не должен требовать платного облачного запроса при каждом синтезе; первоначальная загрузка модели может требовать Интернет.
- Секреты API хранятся локально в `.env`, не включаются в архив/публикацию.
- Бюджетный ориентир проекта: 2 000–5 000 руб./месяц. В отдельном Streamlit-прототипе были настроены плановые ограничения 4 000 руб./месяц, 250 руб./день, 30 руб./задачу и 1 500 руб./нишу; эти ограничения **не реализованы в текущей CLI-ветке** и не должны считаться защитой от расходов.
- В последнем Windows smoke-test версия `piper-tts` определена как 1.8.0, а `piper.EXE` разрешился в `.venv\Scripts`; более ранний прогон запускал глобальный `D:\python\Scripts\piper.EXE`.

## 5. Статусы требований

- **ПОДТВЕРЖДЕНО** — имеется прямое наблюдение/артефакт, подтверждающий именно указанное утверждение.
- **РЕАЛИЗОВАНО, НЕ ПРИНЯТО** — код или файл существует, но критерий приёмки ещё не пройден.
- **ЧАСТИЧНО** — выполнена часть требования, есть незакрытые зависимости/проверки.
- **ОТКРЫТО** — решение или реализация отсутствуют.
- **БЛОКИРУЕТ ПУБЛИКАЦИЮ** — до закрытия нельзя считать решение безопасно готовым для предполагаемой коммерческой публикации.
- **ВНЕ ОБЛАСТИ MVP** — сознательно отложено; не является текущим блокером, если границы MVP не меняются.

## 8. Что подтверждено и какие проблемы частично решены

### 8.1. Репозиторий и архитектура

- Текущей рабочей веткой является CLI-проект `video-farm` с кодом в `src/video_farm/`. Отдельный архив `AI_Video_Factory_RU` — Streamlit-прототип с иной структурой и иным TTS; его код и 32 теста не приписываются CLI-ветке.
- В CLI коде реализована интеграция Piper, генерация WAV по блокам, запись манифеста, создание слайдов и сборка через FFmpeg/FFprobe.
- Архитектура конвейера зафиксирована, но производственный TTS пока не выбран окончательно по юридическим и качественным критериям.
- Реализован ограниченный модуль `src/video_farm/text_normalization.py` версии `0.2.2`, использующий `num2words` для ограниченных числовых шаблонов и родовых форм для известных единиц. Он работает только с явно поддержанными шаблонами и не пытается автоматически склонять любые оставшиеся числа: такие токены должны быть проверены вручную.

### 8.2. Windows/Piper

- В `D:\my_projects\AI_Video_Factory_RU\piper_test\models` уже находились модели `ru_RU-denis-medium` и `ru_RU-dmitri-medium` с JSON-конфигурациями. Модель Дмитрия и конфигурация были скопированы в `video-farm\data\models\piper`; повторная загрузка этих файлов не требовалась.
- Первоначальный Windows-прогон использовал глобальный Piper `D:\python\Scripts\piper.EXE`. В более позднем запуске `doctor` подтвердил Piper TTS 1.8.0 из `video-farm\.venv\Scripts\piper.EXE` и кэшированный голос `ru_RU-dmitri-medium`.
- Команда TTS выполнилась и записала четыре WAV и JSON-манифест. Манифест зафиксировал SHA-256 весов `f073356ebc4bd0f80c5af58df2953a5988bd5bdab1eb38635ce960b071fbefcb` и конфигурации `667ef3117bc642c2892d2ff7690d8bdc8ca4228aeaa783b2dc1416df632855e0d`. Эти значения нужны для воспроизводимости, а не являются подтверждением лицензии.
- В коротком отдельном прямом тесте Piper фраза «Это контрольный тест русской озвучки» звучала нормально. В последующем контрольном сценарии из четырёх блоков пользователь услышал бессвязную речь. Значит, сама успешность процесса и наличие WAV не доказывают качество: вероятная проблема локализуется в передаче/нормализации текста или настройке вызова, но точная причина не установлена.
- Общая заявленная длительность четырёх WAV в том манифесте — 174,451 с на 89 слов по полю `word_count`. Это аномально долго и требует отдельной диагностики, а не признания результата успешным.
- В манифесте, прочитанном через стандартный `Get-Content -Raw`, русские заголовки отображались как mojibake. Для чтения JSON в Windows PowerShell следует использовать `Get-Content -Encoding utf8 ...`; это исправляет отображение JSON и само по себе не объясняет плохой звук.
- UTF-8 hotfix фактически активен в Windows smoke-test: manifest содержит `stdin_encoding=UTF-8` и `child_python_utf8_mode=true`. Минимальный русский текст синтезирован в WAV длительностью 6.699 с; в manifest `quality_warnings=[]`, а при прослушивании sample воспринимается как разборчивая русская речь. Это подтверждает базовую читаемость текста, но не удовлетворяет требование естественности голоса. Пользователь отдельно оценил фрагмент `01_russian_phonetics.wav` как заметно синтетический. В дальнейшем считать критерии разборчивости и естественности раздельно.

## 9. TTS: текущее техническое и лицензионное решение

**Техническая реализация ветки:** Piper остаётся подключённым в CLI, потому что уже интегрирован и проверен на уровне запуска.  
**Решение о производственном голосе:** открыто. По пользовательской оценке Kokoro Dima = 3,5/5 и Piper Dmitri = 2,5/5. Kokoro имеет лучший текущий рейтинг, но оба проваливают внутренний порог 4/5. Техническое создание WAV не равнозначно приемлемому качеству или разрешению на коммерческую публикацию.

### 9.1. Piper

- Пакет `piper-tts` по метаданным upstream указывает GPL-3.0-or-later. GPL допускает коммерческое использование при соблюдении условий, но при распространении самого приложения вместе с GPL-компонентами возникает отдельная задача соблюдения GPL.
- Карточки русских голосов `ru_RU-dmitri-medium` и `ru_RU-denis-medium` указывают CC0 для соответствующего датасета и fine-tuning от `U.S. English Lessac`. Публичная лицензия исходных материалов Lessac ограничивает их использование исследовательскими целями. По доступным документам цепочка прав на эти конкретные downstream-веса и их аудио не подтверждена достаточно однозначно.
- **Статус:** можно продолжать локальное техническое тестирование; не считать коммерческие права выбранного голоса подтверждёнными. До публикации с предполагаемой монетизацией нужно письменное разъяснение по конкретной модели/выходам или замена на голос с однозначной лицензией.

### 9.2. Kokoro-ru v2 — технический прогон выполнен; качество и интеграция не приняты

Проверка актуальных публичных страниц на 25.10.2026:

- Оригинальная `hexgrad/Kokoro-82M` обозначает Apache-2.0 и прямо сообщает о пригодности Apache-лицензированных весов для production и личных проектов.
- Русский порт `zaakirio/kokoro-ru` обозначает лицензию весов `OpenRAIL`; текущая карточка говорит, что код, включая `ru_g2p.py`, — Apache-2.0. Не следует переносить Apache-2.0 базовой модели автоматически на русский fine-tune.
- README русского порта сообщает, что три голоса (Sveta, Masha, Dima) основаны на записях трёх студийных актёров с письменным согласием для открытого выпуска и законного коммерческого использования. Коммерческое использование разрешено с ограничениями OpenRAIL.
- Действующая лицензия датасета Dialogs предоставляет бессрочные безвозмездные права на коммерческое использование при соблюдении §2. Её §3 требует передавать копию лицензии с ограничениями всем получателям при распространении Dataset или производного материала; определение Derivatives прямо включает обученные модели и их выходы. Поэтому остаётся выяснить, как соблюдать flow-down условие, если WAV включён в MP4 и ролик опубликован на VK Видео/RUTUBE.
- Условие распространения нельзя считать автоматически выполненным только от того, что в описании указан факт применения ИИ. Нужно получить практическое разъяснение по публичной публикации, либо спроектировать понятное включение текста лицензии/ограничений и оценить, можно ли реально требовать соблюдения ограничений от получателей.
- README модели указывает известные ограничения качества: точность стрессового/орфоэпического фронтенда 15/16 на тесте автора, ошибки омографов, фиксированную детерминированную просодию и спектральный артефакт на ж/ш/х. Эти заявления автора не заменяют наши тесты на реальных сценариях.
- **Технический прогон Windows от 25.10.2026 выполнен успешно:** тестовый скрипт создал 4 WAV и `manifest.json`, все 4 блока завершены. Репозиторий `zaakirio/kokoro-ru`, revision `d649c57`; runtime `onnxruntime 1.31.0`; Python 3.13.14 x64; `ruaccent 1.5.8.3`, `misaki 0.9.4`, `phonemizer-fork 3.3.2`. SHA-256 модели Dima: `e5bc91f0b15fa85886a82a4fb87e2345fc3de3e6025820a059dde215eb154071`; voice pack: `e774e8859604164aa27c393fa4393c3a4ff2162d37911a39574551edbc801dcb`.
- На идентичном контрольном сценарии Kokoro создал 87,13 секунды аудио за 26,91 секунды синтеза (суммарный RTF ≈0,309, около 3,24× быстрее реального времени); по блокам длительности составили 29,005 / 19,375 / 21,55 / 17,2 секунды. Критерий 4/5 не пройден. Kokoro — предпочтительный кандидат для следующего раунда оптимизации, не утверждённое производственное решение. Коммерческое использование заявлено при соблюдении OpenRAIL, но требование о распространении лицензии/ограничений вместе с выходными материалами остаётся открытым.

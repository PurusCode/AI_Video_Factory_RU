## Проверка WAV

`ffprobe` подтвердил для каждого файла:

- codec: `pcm_s16le`;
- sample rate: `24000` Hz;
- channels: `1`;
- bits per sample: `16`.

Измеренные `ffprobe` длительности совпадают с manifest: 2.725, 3.125 и 3.525 секунды. Manifest имеет `status=complete`, `blocks_expected=3`, `blocks_completed=3`, пустой `quality_warnings` и пустые `unconverted_numeric_tokens` у каждого блока.

## Правила ударений

`data/kokoro_stress_config.json` содержит одно намеренно узкое пользовательское правило `door_lock_nominative_singular`: контекст «дверной замок». Оно не предназначено для фразы «старый замок» и не охватывает родительный падеж. Другие случаи в smoke test не требуют дополнительного пользовательского переопределения по результатам прослушивания. Не расширять regex без отдельной проверки новых словоформ.

## Совместимость с assemble.py

`assemble.py` вызывает `_validate_audio_manifest()` перед созданием видеотаймлайна. Эта функция проверяет соответствие ID сценарию, наличие WAV, безопасность имён файлов и согласованность длительности WAV с manifest. Скрипт `tools/verify_kokoro_assemble_contract.py` из этого пакета запускает именно эту входную проверку на smoke-test артефактах и дополнительно проверяет 24 kHz / mono / PCM16.

Успех этой проверки означает, что WAV и manifest проходят входную валидацию сборщика. Он не является доказательством успешного рендера MP4.

## Что ещё не принято

- Полный рендер тестового MP4 с реальными слайдами.
- Проверка общей длительности, синхронизации речи и смены слайдов.
- Прослушивание итоговой звуковой дорожки после сборки FFmpeg.
- Регрессионные тесты полного пайплайна с Kokoro.
- Ручная приёмка короткого видео.

Следовательно, production TTS smoke test пройден, но этап интеграции целиком и MVP как производственная система ещё не приняты.

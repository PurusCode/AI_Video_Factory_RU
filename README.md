# video-farm — локальная фабрика русскоязычных видео

<!-- KOKORO_SHORT_E2E_ACCEPTANCE_STATUS -->
> **Актуальный статус Kokoro на 05.11.2026:** production CLI использует Kokoro-ru v2 Dima через ONNX Runtime CPU. На целевой Windows-машине подтверждены: реальный синтез 3/3 WAV (revision `d649c57`, голос `dima`, manifest `complete`); входная проверка WAV/manifest функцией контракта `assemble.py`; 82 автоматических теста; `compileall`; проверка `doctor`; создание 3 RGB-слайдов и короткого MP4 smoke test длительностью 9,36 с (H.264 1280×720 / 25 fps, AAC 44,1 kHz stereo). Пользователь прослушал все три WAV и просмотрел MP4, подтвердив нормальное звучание, порядок фраз и соответствие слайдам. Это короткая техническая приёмка, а не готовность к регулярному производству: этап 3 остаётся открытым до полноценного 7–9-минутного прогона с реальными лицензируемыми визуалами и атрибуцией, проверки числовой нормализации и сценариев отказа, подготовки `THIRD_PARTY_LICENSES.md` и приёмки publish package.

MVP-пайплайн для Windows 10/11: исследование темы → JSON-сценарий → локальная озвучка → лицензируемые стоки → PNG-слайды → MP4 H.264/AAC → описание и QC-отчёт. Код организован так, чтобы один человек мог запускать этапы отдельно или одной командой.


> **Статус поставки:** это рабочий каркас MVP с автоматическими тестами и примерами сценариев. Полная готовность к регулярному производству ещё не подтверждена. Для полного прогона могут потребоваться ключи YouTube, Pexels/Pixabay и работающий LLM-провайдер. Ключи не встроены. Без ключей внешние API не имитируются. Загрузка в RUTUBE/VK намеренно не включена: публикация выполняется вручную после проверки человеком.

## 2. Текущий статус TTS

### 2.1. Целевое решение

Основной TTS проекта — **Kokoro-ru v2, голос Dima**, локальный ONNX Runtime CPU.

Основания:
- пользовательская оценка естественности 4/5 от 03.11.2026;
- изолированный CPU benchmark на целевой Windows-машине;
- средний RTF около 0,307 в повторном тесте 05.11.2026;
- проверенные контекстные правила ударения и нормализации на контрольных примерах.

Piper Dmitri получил пользовательскую оценку 2,5/5 и больше не является целевым производственным движком.

### 2.2. Production CLI: Kokoro-ru v2 Dima

После установки обновлённых зависимостей команда `tts` использует Kokoro-ru v2 Dima через ONNX Runtime CPU. Команда:

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli tts --script output\script.json --out output\audio
```

использует production backend Kokoro. Piper не вызывается и не используется как резервный движок.

Benchmark-окружение `.kokoro-venv` остаётся изолированным. Production CLI использует отдельный runtime из `.venv`; модель и RUAccent assets находятся в `data/models/`. Автоматического fallback на Piper нет. При ошибке модели, G2P или ONNX синтез завершается ошибкой и сохраняет `status=failed` в manifest.

### 2.3. Лицензирование Kokoro

Лицензионная цепочка содержит отдельные компоненты:
- русские веса — OpenRAIL;
- базовая модель Kokoro-82M — Apache-2.0;
- русский G2P-код — Apache-2.0 согласно материалам проекта;
- RUAccent — MIT;
- Dialogs dataset — OpenRAIL.

Нельзя описывать всю цепочку как Apache-2.0.

§3 Dialogs OpenRAIL остаётся документированным остаточным риском. Проект принял решение не считать его блокером локальной технической интеграции, но это не юридическая гарантия соответствия любого способа распространения MP4. До первой производственной сборки необходимо создать `THIRD_PARTY_LICENSES.md` по фактическому production dependency tree.

Подробности: `docs/07_kokoro_ru_licensing_review.md` и `docs/11_KOKORO_PRODUCTION_AND_LICENSE_DECISION.md`.

### Подготовка RUAccent assets при чистой установке

Кеш модели Kokoro и данные RUAccent — **два отдельных набора файлов**. Наличие модели Kokoro в `data/models/kokoro-ru-v2-onnx` не означает, что подготовлены данные RUAccent. Файл `data/kokoro_stress_config.json` содержит пользовательский словарь и контекстные правила; он **не заменяет** модели и словари RUAccent.

До первого production-синтеза подготовьте локальные RUAccent assets в `data/models/ruaccent-accentuator`. Production helper предварительно проверяет наличие следующих каталогов и не выполняет их автоматическую загрузку:

```text
data/models/ruaccent-accentuator/
├── dictionary/
└── nn/
    ├── nn_accent/
    ├── nn_stress_usage_predictor/
    └── nn_yo_homograph_resolver/
```

Используйте совместимый снимок данных RUAccent из [официального репозитория RUAccent](https://github.com/Den4ikAI/ruaccent) и [репозитория данных RUAccent на Hugging Face](https://huggingface.co/ruaccent/accentuator). Сохраняйте исходную структуру каталогов. Дополнительные файлы/подкаталоги могут требоваться выбранной версией RUAccent и моделью омографов; перед production-развёртыванием зафиксируйте полный revision снимка и проверьте полный набор на чистой установке. Не считайте изменяемую ветку `main` воспроизводимой фиксацией версии.

Проверяйте наличие RUAccent assets командой `video-farm doctor` и выполняйте контрольный синтез до сборки видео. Не добавляйте assets и веса моделей в Git.

### Статус benchmark lock-файла и production dependencies

`requirements-kokoro-py313.lock.txt` — отдельный lock-файл изолированного benchmark-окружения, а не автоматически используемый production lock. В нём нет hash-записей. Production-набор зависимостей определяется `pyproject.toml` и `install.ps1`; перед формированием `THIRD_PARTY_LICENSES.md` снимите фактический список именно из production `.venv` командой `python -m pip freeze --all` и сопоставьте его с этими декларациями. Не используйте benchmark lock как доказательство состава production-окружения.

## 3. Требования к окружению и быстрый старт

- Windows 10/11 x64.
- Python 3.12 или 3.13 x64.
- FFmpeg и FFprobe из одной сборки, доступны из `PATH`.
- Интернет для первоначальной загрузки моделей и обращения к внешним API.
- Достаточно места на диске для Python-зависимостей, моделей, TTS-кэша, исходных материалов и выходных видео.
- Секреты API хранятся локально в `.env`, не включаются в Git.
- Для этого проекта рекомендован ASCII-путь, например `D:\video-farm`, чтобы снизить риск проблем ML-библиотек с кириллицей в пути.

Целевая машина проекта:
- Intel Core i5-11400;
- 32 GB RAM;
- без дискретной видеокарты.

Изолированный Kokoro benchmark проверялся на CPU. Не переносите показатели с GPU или оборудования авторов модели на целевую машину без отдельного измерения.

### Установка текущей версии

1. Распакуй проект в рабочую папку.
2. Установи Python 3.12/3.13 и FFmpeg. Проверь в новом PowerShell:

```powershell
python --version
ffmpeg -version
ffprobe -version
```

3. Установи зависимости текущей версии проекта:

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\install.ps1
```

Установщик создаёт `.venv` и устанавливает production-зависимости Kokoro. При обновлении существующего окружения установщик не удаляет каталог `.kokoro-venv`; он остаётся отдельным benchmark-окружением.

4. Скопируй `.env.example` в `.env` и добавь только нужные ключи. Не публикуй и не коммить `.env`.
5. Проверь систему:

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli doctor
```

6. Запусти тестовый черновой цикл (после подготовки сценария и настройки нужных сервисов):

```powershell
.\run.ps1 -Topic "Как выбрать первую локальную нейросеть" -Name "local-ai-guide" -Draft
```

Убери `-Draft` для финального рендера. Материалы появятся в `output\runs\local-ai-guide\`.

## 4. Конфигурация провайдеров

Скопируй `.env.example` в `.env` (установщик может создать шаблон автоматически). Не записывай секреты в Git или issue.

### LLM

`LLM_PRIMARY_BASE_URL`, `LLM_PRIMARY_API_KEY`, `LLM_PRIMARY_MODEL` описывают основной OpenAI-compatible провайдер. В конфигурации проекта может использоваться локальный Ollama (`http://localhost:11434/v1`, `qwen2.5:3b`). Установи Ollama, скачай совместимую модель и запусти сервер.

`LLM_SECONDARY_*` — необязательный резервный провайдер. Указывай только официальный endpoint, модель и ключ от сервиса, которым вправе пользоваться. Доступность тарифов и правила доступа могут меняться и не гарантируются кодом.

Официальную документацию и условия перепроверяй перед настройкой:
- Yandex AI Studio: <https://aistudio.yandex.ru/en/docs/ai-studio/api/>
- DeepSeek API: <https://api-docs.deepseek.com/quick_start/>
- Ollama: <https://github.com/ollama/ollama>

Не отправляй секретные или персональные данные во внешний LLM без проверки условий обработки.

### YouTube Data API

Для поиска кандидатов укажи `YOUTUBE_API_KEY`. Используется официальный YouTube Data API v3 (`search.list`, `videos.list`); программа не парсит HTML YouTube. Создай проект в Google Cloud Console, включи YouTube Data API v3 и выпусти ключ.

У API есть отдельные квоты для `search.list` и общий бюджет для остальных методов. Некоторые статистические значения могут быть скрыты или недоступны. Производные показатели из API Data не вычисляются без отдельного разрешения YouTube.

### Ежедневный поиск популярных видео (Discovery)

Команда `discover` предназначена для поиска кандидатов по нескольким широким направлениям, а не только по ИИ. Она охватывает:
- новости;
- технологии и науку;
- экономику и бизнес;
- спорт;
- игры;
- кино, музыку и развлечения;
- автомобили;
- путешествия, еду и образ жизни;
- образование и историю;
- дом, ремонт и DIY.

Российская выдача и международная выдача с приоритетом английского языка показываются раздельно.

Запуск:

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli discover
```

По каждому направлению используются периоды последних 24 часов и 7 дней. Сортировка отражает исходную сортировку YouTube API `viewCount`. Дополнительно запрашивается официальный `mostPopular` чарт для регионов RU и US; он не покрывает все тематики.

Отчёты:
- `output\discovery\discovery.md`;
- `output\discovery\discovery.json`.

В JSON `unique_candidates` содержит дедуплицированные по ID ролики, а `found_in` — поисковые наборы, в которых найден каждый ролик. Markdown показывает до 10 первых роликов на набор.

**Ограничения:** общее число просмотров не является скоростью их прироста. По одному запуску нельзя определить вирусность или скорость роста. Проект не рассчитывает собственный трендовый балл и автоматически не назначает производные теги тем. Для таких производных метрик необходимо отдельно проверять условия YouTube API и наличие требуемых разрешений.

Старая команда `analyze` может оставаться отключённой в актуальной конфигурации, если её производные показатели несовместимы с действующим режимом использования API. Не считай наличие команды доказательством разрешённости соответствующего аналитического сценария.

#### Актуализация Discovery Stage 5.1 — 03.11.2026

- Отдельные поисковые наборы `viewCount` и `date`.
- 10 направлений × 2 рынка × 2 периода × 2 порядка = 80 первых страниц в стандартном плане.
- По умолчанию `maxResults=50`, `max-pages=1`.
- Дневной журнал `data/usage/youtube_search_quota.json` учитывает до 90 попыток `search.list` за Pacific-день, включая неуспешные; 10 вызовов остаются резервом.
- Внешние обращения сверяются командой `discover-quota --external-search-calls N`.
- Подробности: `docs/TREND_DISCOVERY_STAGE5_1.md`.

### Стоки

Для поиска и скачивания клипов/фото заполни `PEXELS_API_KEY` и/или `PIXABAY_API_KEY`. Кэш поисковых ответов используется повторно. Размеры и параметры файлов ограничены настройками проекта.

Официальная документация:
- Pexels API: <https://www.pexels.com/api/documentation/>
- Pixabay API: <https://pixabay.com/api/docs/>

Перед публикацией проверь страницу каждого клипа/фото, действующую лицензию, возможные права на изображение человека, товарные знаки, логотипы, интерфейсы и другие ограничения. Бесплатное скачивание не означает, что конкретный материал подходит для любого коммерческого использования. Программа хранит исходные URL, автора и источник в `assets_manifest.json`.

## 5. Команды CLI

Все команды выполняются из корня проекта после установки зависимостей.

### Диагностика

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli doctor
```

### Анализ и идеи

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli analyze --out output/analysis --per-query 25 --days 365
.\.venv\Scripts\python.exe -m video_farm.cli topics --analysis output/analysis/analysis.json --out output/topics.json --count 20
```

Учитывай ограничения текущего режима YouTube API. Этапы `analyze` и `topics` не являются обязательным блокером создания видео по уже выбранной теме.

### Создание сценария

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli script --topic "Тема видео" --out output/script.json
```

### Озвучка

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli tts --script output/script.json --out output/audio --speed 0.9
```

**Важно:** команда использует Kokoro-ru v2 Dima. При первом запуске требуется интернет для получения закреплённой revision модели. WAV и `manifest.json` совместимы с монтажным модулем; Piper fallback отсутствует.

### Поиск и загрузка стоков

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli assets --script output/script.json --out output/assets_manifest.json --max-keywords 30
```

Манифест источников создаётся и при отсутствии ключей, но без доступного API реальные стоки не будут скачаны.

### Создание слайдов

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli slides --script output/script.json --assets output/assets_manifest.json --out output/slides
```

Целевой профиль — PNG 1920×1080 RGB.

### Сборка черновика

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli assemble --script output/script.json --audio-dir output/audio --slides-dir output/slides --assets output/assets_manifest.json --out output/video.mp4 --draft
```

Полный список параметров доступен через `--help`.

## 6. Что создаётся

Для запуска `run --name example` ожидаются следующие артефакты (точный состав зависит от команды и конфигурации):

- `script.json` — сценарий, блоки озвучки, типы слайдов, ключевые слова и факты для проверки;
- `audio\*.wav` и `audio\manifest.json` — отдельная озвучка и измеренная длительность каждого блока;
- `assets_manifest.json` — источники, URL, авторы и локальные файлы;
- `slides\slide_*.png` и `slides_manifest.json` — непрозрачные RGB-слайды;
- `example.mp4` — итоговый ролик; B-roll — отдельные вставки между слайдами, а не прозрачный overlay;
- `example.qc.json` — отчёт FFprobe по длительности, разрешению, видео-/аудиокодекам и битрейту;
- `publish.txt` и `publish.json` — описание, хэштеги, атрибуция источников и предупреждения QC.

Финальный целевой профиль ориентирован на 1920×1080, H.264 High, 25 fps, GOP 50, AAC-LC stereo 44.1 kHz / 128 kbps и целевой видеобитрейт 4500 kbps. Контейнеры/энкодеры могут дать небольшие отличия фактического битрейта; ориентируйся на QC-отчёт и требования площадки на дату загрузки. `--draft` использует облегчённые настройки и не предназначен для публикации.

## 8. Редакторская проверка обязательна

Автоматическая генерация не заменяет модерацию. Перед публикацией:

1. Открой `fact_checks` в сценарии и проверь утверждения, даты, версии моделей, цены API и условия лицензий.
2. Прослушай всю озвучку, не только первый блок.
3. Проверь ударения, склонение чисел, английские термины, аббревиатуры и паузы.
4. Проверь соответствие речи слайдам и B-roll.
5. Проверь лицензии и исходные страницы визуальных материалов.
6. Просмотри итоговый MP4 целиком.
7. Проверь FFprobe QC.
8. Убедись, что в publish package атрибутированы именно использованные материалы.
9. Самостоятельно дай финальное разрешение на публикацию.

## 9. Что отложено за пределы MVP

Автозагрузка в RUTUBE/VK, пакетный ночной запуск на нескольких каналах, веб-дашборд и progressive reveal не входят в первую версию. Публикация требует отдельного ручного подтверждения.

Монетизационные формальности, выплаты и связанные интеграции исследуются ближе к достижению актуальных порогов платформ. Это не отменяет необходимости проверять права на контент и применимые требования с первой публикации.

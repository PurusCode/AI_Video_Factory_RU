# video-farm — локальная фабрика технологических видео

MVP-пайплайн для Windows 10/11: анализ YouTube → идеи → JSON-сценарий → локальная озвучка Piper → лицензируемые стоки → PNG-слайды → MP4 H.264/AAC → описание и QC-отчёт. Код организован так, чтобы один человек мог запускать этапы отдельно или одной командой.

> **Статус поставки:** это рабочий каркас MVP с тестами и примером сценария. Полный видеопрогон требует установки Piper TTS и FFmpeg и ключей API (YouTube для аналитики; Pexels/Pixabay для стоков; LLM API или работающего Ollama). Ключи не встроены. Без ключей стоки не скачиваются, а анализ YouTube не имитируется. Загрузка в Rutube/VK намеренно не включена: используйте только официально разрешённый API и отдельное подтверждение человека.

> **Статус требований и TTS на 26.10.2026:** единый SRS — `docs/01_SRS.md`. Piper Dmitri оценён пользователем в 2,5/5, Kokoro-ru v2 Dima — 4/5 (внутренний порог качества достигнут по пользовательской оценке); коммерческие/дистрибуционные условия и интеграция Kokoro в основной CLI остаются открытыми и пока не приняты в производство. Ручная предварительная запись чисел словами дала положительный результат. В этой ветке добавлен ограниченный автоматический нормализатор `voice_text` версии 0.2.2 для дат, времени, процентов, известных единиц, валют и некоторых обозначений моделей; настоящий `num2words 0.5.14` был проверен на Windows с v0.2.1, выявлены пробелы склонения; родовой патч v0.2.2 и его WAV ещё требуют Windows-приёмки. Он не угадывает падеж для произвольных чисел: непроработанные цифры остаются в `normalized_voice_text`, попадают в `unconverted_numeric_tokens` и вызывают предупреждение QC. Числовая нормализация использует `num2words`, который устанавливается вместе с TTS через `install.ps1` или командой `python -m pip install -e ".[tts]"`. Kokoro остаётся отдельным benchmark-кандидатом; коммерческое лицензирование обоих вариантов пока не закрыто. Для проверки используйте `docs/10_windows_normalizer_validation.md`; остальные решения: `docs/DECISION_TTS.md`, `docs/06_piper_licensing_audit.md`, `docs/07_kokoro_ru_licensing_review.md` и `docs/09_tts_text_normalization_plan.md`. Отдельный архив `AI_Video_Factory_RU` содержит другой Streamlit-прототип.

## 1. Требования

Единая спецификация требований, статусов проверок и открытых вопросов: [`docs/01_SRS.md`](docs/01_SRS.md). В ней различаются автоматические тесты, синтетический smoke-test и ручная приёмка реального голоса/ролика.

- Windows 10/11 x64.
- Python 3.12 или 3.13 x64.
- FFmpeg и ffprobe из одной сборки, доступны из `PATH`.
- Интернет для первичной загрузки модели Piper и для API стоков/LLM/YouTube.
- Достаточно места на диске: Python-зависимости, модели LLM (если локальные) и кэш TTS занимают место; итоговые 1080p-видео тоже могут быть крупными.
- Для этого проекта рекомендован ASCII-путь, например `D:\video-farm`, чтобы не сталкиваться с проблемами некоторых ML-библиотек из-за кириллицы в пути.

## 2. Быстрый старт в PowerShell

1. Распакуй проект в `D:\video-farm`.
2. Установи Python 3.12/3.13 и FFmpeg. Проверь в новом PowerShell:
   ```powershell
   python --version
   ffmpeg -version
   ffprobe -version
   ```
3. Установи зависимости:
   ```powershell
   Set-ExecutionPolicy -Scope Process Bypass
   .\install.ps1
   ```
   Установщик создаёт `.venv` и устанавливает Piper TTS для CPU (версия 1.8+; Windows x64).
4. Открой `.env` и добавь необходимые ключи. Этот файл не следует публиковать или коммитить.
5. Проверь систему:
   ```powershell
   .\.venv\Scripts\python.exe -m video_farm.cli doctor
   ```
6. Запусти полный цикл для своей темы:
   ```powershell
   .\run.ps1 -Topic "Как выбрать первую локальную нейросеть" -Name "local-ai-guide" -Draft
   ```
   Убери `-Draft` для финального CBR-рендера. Все материалы появятся в `output\runs\local-ai-guide\`.

При первом запуске Piper скачивает русскую модель и её конфигурацию в `data\models\piper`, последующие запуски используют файлы с диска. Путь модели локальный; каталоги возможного ML-кэша заранее направлены в `data\cache`, вне `%USERPROFILE%`.

## 3. Конфигурация провайдеров

Скопируй `.env.example` в `.env` (установщик делает это автоматически).

### LLM

`LLM_PRIMARY_BASE_URL`, `LLM_PRIMARY_API_KEY`, `LLM_PRIMARY_MODEL` описывают основной OpenAI-compatible провайдер. По умолчанию это локальный Ollama (`http://localhost:11434/v1`, `qwen2.5:3b`). Установи Ollama, скачай совместимую модель и запусти сервер. На слабом CPU генерация может быть очень медленной; используй более компактную модель.

`LLM_SECONDARY_*` — необязательный резервный провайдер. Укажи только официальный endpoint, модель и ключ от сервиса, которым вправе пользоваться. Роутер пробует провайдеры по порядку и переходит к следующему при ошибке. Доступность бесплатных тарифов и правила доступа меняются — они не гарантируются кодом.

Примеры официальной документации, которую нужно перепроверить перед настройкой:
- Yandex AI Studio: <https://aistudio.yandex.ru/en/docs/ai-studio/api/>
- DeepSeek API: <https://api-docs.deepseek.com/quick_start/>
- Ollama: <https://github.com/ollama/ollama>

Не отправляй секретные/персональные данные во внешний LLM без проверки условий обработки.

### YouTube Data API

Для поиска кандидатов укажи `YOUTUBE_API_KEY`. Используется официальный YouTube Data API v3 (`search.list`, `videos.list`); программа не парсит HTML YouTube. Создай проект в Google Cloud Console, включи YouTube Data API v3 и выпусти ключ. У API есть отдельные квоты для `search.list` и общий бюджет для остальных методов. Некоторые значения статистики могут быть скрыты или недоступны. Производные показатели из API Data не вычисляются без отдельного разрешения YouTube.

### Ежедневный поиск популярных видео (Discovery v2)

Команда `discover` заменяет прежний поиск только по ИИ. По умолчанию она охватывает 10 широких направлений: новости; технологии и наука; экономика и бизнес; спорт; игры; кино, музыка и развлечения; автомобили; путешествия, еда и образ жизни; образование и история; дом, ремонт и DIY. Российская выдача и международная выдача с приоритетом английского языка показываются раздельно.

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli discover
```

Для каждого направления выполняется поиск за последние 24 часа и 7 дней. Сортировка — исходная сортировка YouTube API `viewCount`; запрашивается до двух страниц на поисковый набор. Ограничение — до 90 вызовов `search.list` за запуск. Дополнительно запрашивается официальный `mostPopular` чарт для RU и US; по документации он охватывает прежде всего музыкальные, кино- и игровые видео и не заменяет поиск по остальным направлениям.

Отчёты: `output\discovery\discovery.md` и `output\discovery\discovery.json`. В JSON `unique_candidates` содержит дедуплицированные по ID ролики, а `found_in` — поисковые наборы, в которых найден каждый ролик. Markdown показывает до 10 первых роликов на набор.

Скорость прироста просмотров, вирусность, собственный трендовый балл и автоматические теги тем не рассчитываются. Общие просмотры не равны скорости роста. YouTube ограничивает создание производных метрик и контентной категоризации; такие функции требуют отдельного одобрения для аналитического use case. Поиск сортирует и показывает исходные значения API. Международный поиск выполняется без `regionCode`, но с `relevanceLanguage=en` как приоритетом, а не как строгим языковым фильтром.

У `search.list` отдельный ежедневный лимит по числу вызовов; каждая дополнительная страница тоже расходует вызов. `videos.list` вызывается пакетно для статистики найденных уникальных видео. Неавторизованные данные API нужно обновить или удалить в пределах 30 календарных дней; для очистки есть команда `discover-cleanup --out output\discovery`. См. `docs/TREND_DISCOVERY_STAGE2.md`.

Старая команда `analyze` остаётся отключённой: её производные показатели несовместимы с текущим режимом использования API. Старая `topics` не формирует тренды дня из этого отчёта.

### Стоки

Для поиска и скачивания клипов/фото заполни `PEXELS_API_KEY` и/или `PIXABAY_API_KEY`. Кэш поисковых ответов хранится не менее 24 часов; повторные запросы используют его. Файлы ограничены размером 50 МБ, видео — 5–60 секунд и минимум 1280×720. API не обходятся через скрытые прокси или искусственное увеличение квоты.

- Pexels API: <https://www.pexels.com/api/documentation/>
- Pixabay API: <https://pixabay.com/api/docs/>

Перед публикацией проверь страницу каждого клипа/фото, действующую лицензию, возможные права на изображение человека, товарные знаки, логотипы, экранные интерфейсы и другие ограничения. «Бесплатно скачать» само по себе не означает, что любой конкретный материал подходит для любого коммерческого использования. Программа хранит исходные URL, автора и источник в `assets_manifest.json`.

## 4. Команды CLI

Из корня проекта, после установки:

```powershell
# Проверка окружения
.\.venv\Scripts\python.exe -m video_farm.cli doctor

# Анализ YouTube по data/queries.txt
.\.venv\Scripts\python.exe -m video_farm.cli analyze --out output/analysis --per-query 25 --days 365

# 20 тем по найденной аналитике (при недоступной LLM есть локальный резервный список)
.\.venv\Scripts\python.exe -m video_farm.cli topics --analysis output/analysis/analysis.json --out output/topics.json --count 20

# Сценарий по выбранной теме
.\.venv\Scripts\python.exe -m video_farm.cli script --topic "Тема видео" --out output/script.json

# Озвучка блоков сценария
.\.venv\Scripts\python.exe -m video_farm.cli tts --script output/script.json --out output/audio --speed 0.9

# Стоки; манифест создаётся даже если ключи не заданы
.\.venv\Scripts\python.exe -m video_farm.cli assets --script output/script.json --out output/assets_manifest.json --max-keywords 30

# PNG-слайды 1920x1080 RGB
.\.venv\Scripts\python.exe -m video_farm.cli slides --script output/script.json --assets output/assets_manifest.json --out output/slides

# Сборка черновика или финала
.\.venv\Scripts\python.exe -m video_farm.cli assemble --script output/script.json --audio-dir output/audio --slides-dir output/slides --assets output/assets_manifest.json --out output/video.mp4 --draft
```

Полный список параметров доступен в `--help` после команды. Этапы `analyze` и `topics` не являются обязательным блокером для создания видео по уже выбранной теме.

## 5. Что создаётся

Для `run --name example`:

- `script.json` — сценарий, блоки озвучки, типы слайдов, ключевые слова и список фактов для проверки.
- `audio\*.wav` + `audio\manifest.json` — отдельная озвучка и измеренная длительность каждого блока.
- `assets_manifest.json` — источники, URL, авторы и локальные файлы.
- `slides\slide_*.png` и `slides_manifest.json` — полноценные непрозрачные RGB-слайды.
- `example.mp4` — финальный ролик; в монтажной логике B-roll — отдельные вставки между слайдами, не прозрачный overlay.
- `example.qc.json` — отчёт ffprobe по длительности, разрешению, видео-/аудиокодекам и битрейту.
- `publish.txt` + `publish.json` — описание, хэштеги, атрибуция источников и напоминание о проверке фактов.

Финальный рендер ориентирован на 1920×1080, H.264 High, 25 fps, GOP 50, AAC-LC stereo 44.1 kHz / 128 kbps и целевой видеобитрейт 4500 kbps. Некоторые контейнеры/энкодеры могут дать небольшие отличия фактического битрейта; ориентируйся на QC-отчёт, а требования площадки перепроверяй перед загрузкой. `--draft` использует облегчённые настройки и не предназначен для публикации.

### Воспроизводимая проверка Piper

Перед первым производственным прогоном выполни диагностику и отдельный контрольный синтез:

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli doctor
.\.venv\Scripts\python.exe -m video_farm.cli tts --script data/piper_control_script.json --out output/piper-control --speed 1.0
```

Сценарий `data/piper_control_script.json` содержит четыре коротких блока: русская речь и паузы, числовая дата/проценты/единицы измерения, английские названия и аббревиатуры. Команда сохраняет WAV и `output/piper-control/manifest.json`. В манифест записываются версия Python и Piper (если доступна в метаданных пакета), ОС, SHA-256 модели и конфигурации голоса, длительность и параметры каждого WAV, время синтеза и хеш нормализованного текста. Дата вида `16.10.2026` нормализуется до `16 октября 2026 года`.

После синтеза нужно вручную прослушать **все четыре WAV** и проверить произношение названий, чисел, ударения, паузы и естественность темпа. Наличие файлов и успешный QC сами по себе не подтверждают качество речи. Если диагностика сообщает, что Piper не найден, запуск синтеза продолжать не следует: сначала нужно исправить установку в `.venv`.

## 6. Тестовый пример

В `examples/deepseek_v4_1_flash/script.json` находится готовый пример по теме «DeepSeek V4.1 Flash локально: реальная цена запуска» с 7 блоками и более 1100 слов. В сценарий добавлены официальные ссылки для фактчекинга. Численные оценки хранения весов помечены как приблизительные расчёты, а доступность конкретного локального релиза обязательно проверяется перед публикацией.

Собрать из него тестовое видео:

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli run --script-file examples/deepseek_v4_1_flash/script.json --name deepseek-v4-1-flash --draft
```

Команда всё равно требует работающую локальную Piper TTS. Если ключи стоков не заданы, будет собрана версия со слайдами без реальных стоковых вставок, и QC напишет предупреждение. Чтобы выполнить критерий по B-roll, добавь Pexels/Pixabay API-ключи и повтори прогон.

### Лицензия голоса TTS

По умолчанию для технических тестов выбран мужской Piper-голос `ru_RU-dmitri-medium`. В карточке его датасет указан как CC0, а страница репозитория `piper-voices` отмечена MIT; однако карточка одновременно говорит, что модель дообучена на базе U.S. English Lessac. Официальная лицензия исходных материалов Lessac исключает коммерческое использование, поэтому права на коммерческое использование именно этого голоса и его аудиовыхода пока НЕ подтверждены. У модели `ru_RU-denis-medium` та же заявленная родословная. Кроме того, установленный пакет `piper-tts` может иметь лицензию GPL-3.0-or-later; это отдельный вопрос от прав на голос. До монетизированной публикации необходимо получить письменное разъяснение по цепочке прав или выбрать голос с однозначно подтверждённой коммерческой лицензией. Подробности и первичные ссылки — `docs/06_piper_licensing_audit.md`. Озвучка тестового текста записывается в WAV локально; модель весит около 63 МБ.

## 7. Редакторская проверка обязательна

Автоматическая генерация не заменяет модерацию. Перед публикацией открой `fact_checks` в сценарии и проверь все утверждения, даты, версии моделей, цену API и условия лицензии. Слайды с графиками из шаблона являются иллюстративной композицией, если у них нет привязанных проверенных данных; не выдавай их за реальные измерения. Избегай логотипов/брендов в стоковых материалах и не используй чужие видео как «референс для копирования». Внешнюю музыку проект не добавляет, пока не будет указан отдельный проверенный источник и лицензия.

Для рутинной работы человека остаётся три действия: выбрать тему, проверить факты/материалы, дать финальное разрешение на публикацию.

## 8. Что отложено за пределы MVP

Автозагрузка в Rutube/VK, пакетный ночной запуск на 5 каналов, веб-дашборд и progressive reveal не включены в первую версию. Публикация требует отдельного ручного подтверждения. Для YouTube используется официальный API; его квоты ограничены, поэтому анализ выполняется явно по команде, а не в бесконечном цикле.

## Ежедневное обнаружение популярных видео (Discovery v2)

Команда `discover` теперь по умолчанию ищет кандидатов не только по ИИ, а по 10 широким направлениям: новости, технологии и наука, экономика, спорт, игры, развлечения, автомобили, путешествия/еда/образ жизни, образование/история и DIY/дом. Российская выдача и международная выдача разделяются. Для международной выдачи не задаётся `regionCode`, а `relevanceLanguage=en` используется только как языковой приоритет.

По каждому направлению собираются результаты за последние 24 часа и 7 дней, сортировка `viewCount`; скрипт получает до двух страниц на набор и ограничивает число `search.list` вызовов 90 за запуск. Дополнительно запрашивается официальный чарт `mostPopular` для регионов RU и US. Этот чарт полезен как дополнительный источник, но официальная документация описывает его как ориентированный прежде всего на музыку, кино и игры — он не покрывает все тематики.

Запуск:

```powershell
.\.venv\Scripts\python.exe -m video_farm.cli discover
```

Дополнительные параметры:

```powershell
# Изменить число результатов на странице и число страниц
.\.venv\Scripts\python.exe -m video_farm.cli discover --max-results 25 --max-pages 2 --search-call-budget 90

# Выполнить отдельный пользовательский поиск вместо всех направлений
.\.venv\Scripts\python.exe -m video_farm.cli discover --query "локальные нейросети|автоматизация дома"
```

Отчёт: `output\discovery\discovery.md` и `output\discovery\discovery.json`. В JSON есть объединённый список `unique_candidates` и поле `found_in`, показывающее, в каких поисковых наборах встретилось видео. В Markdown для каждого набора выводятся первые 10 результатов, JSON содержит всю полученную выборку.

**Важные ограничения.** Общий `viewCount` не является скоростью роста. По одному запуску нельзя определить, какое видео быстро набирает популярность. Для вычисления скорости, собственных трендовых баллов и автоматического присвоения видео тем/тегов нужно сначала получить соответствующее разрешение YouTube на дополнительные производные метрики; без него Discovery v2 сохраняет сырые поля API, порядок API и только происхождение поисковых запросов. См. `docs/TREND_DISCOVERY_STAGE2.md`.

## Актуализация Discovery Stage 5.1 — 03.11.2026

Discovery выполняет отдельные поисковые наборы `viewCount` и `date`: 10 направлений × 2 рынка × 2 периода × 2 порядка = 80 первых страниц. По умолчанию `maxResults=50`, `max-pages=1`. Дневной журнал `data/usage/youtube_search_quota.json` учитывает до 90 попыток `search.list` за Pacific-день, включая неуспешные; 10 вызовов остаются резервом. Внешние обращения необходимо сверять через `discover-quota --external-search-calls N`. Подробности и ограничения — `docs/TREND_DISCOVERY_STAGE5_1.md`.
